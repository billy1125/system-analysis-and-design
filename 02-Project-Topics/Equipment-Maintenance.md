# 設備保養紀錄管理系統

> **領域**：設備維護｜**難度**：標準｜**這一題要想清楚的問題**：「下次保養日」是算出來的還是填出來的？沒按時保養的那一次要不要留下來？
>
> 五題共通的名詞見本資料夾的[期末設計題目說明](README.md)〈五〉。

---

## 一、先看懂這件事在說什麼

### 1.1 一個你已經懂的類比

機車每半年或每 3,000 公里要換一次機油。**沒換不會馬上壞，但拖久了引擎會出問題。**

保養廠會在你的保養手冊上蓋一個章，寫下這次的日期與里程，然後告訴你下次大概什麼時候要再來。你自己記不記得是一回事，手冊上有沒有紀錄是另一回事——賣車的時候，那本手冊會決定車子值多少錢。

**工廠的設備保養就是同一件事，只是設備比機車多、週期比機車雜、而且忘記保養的代價是停線。**

### 1.2 現場實際長什麼樣

工廠裡的設備需要定期保養：換油、清潔、上潤滑、更換耗材、校正、檢查皮帶與軸承。做這件事的目的是**在壞掉之前處理掉**，因為設備突然停下來的代價遠高於保養的成本。

一間中小型工廠的實際狀況大致是這樣：

| 面向 | 現況 |
|---|---|
| 設備數量 | 幾十台到一兩百台，每台有自己的編號，例如 `EQ-012` |
| 保養週期 | 每台不同，也可能同一台有好幾種週期：日常點檢每天、月保養每月、大保養每年 |
| 誰在做 | 日常點檢由操作員自己做；比較深的保養由保養人員做 |
| 怎麼記 | **設備旁邊掛一張表，做完打勾簽名。** 月底收回來歸檔 |
| 怎麼知道該保養了 | 保養人員自己排、自己記，或看牆上的年度保養計畫表 |

出問題通常是在設備突然停下來的時候：

> 「這台上次保養是什麼時候？」
> 「表在設備旁邊，我去拿……上面最後一次簽名是三個月前。」
> 「那中間兩次呢？」
> 「不知道，可能忘了簽。」

### 1.3 名詞解釋

| 名詞 | 意思 |
|---|---|
| 設備 | 生產用的機器，例如沖床、CNC、射出機、輸送帶、空壓機 |
| 預防保養（PM，Preventive Maintenance） | 在設備還沒壞之前，依固定週期做的保養 |
| 事後維修（BM，Breakdown Maintenance） | 壞了才修。**本題只做預防保養，不做故障維修** |
| 保養項目 | 一次保養要做哪幾件事，例如「檢查油位、清潔濾網、上潤滑油」 |
| 保養週期 | 兩次保養之間的間隔，例如 30 天、90 天、365 天 |
| 保養計畫 | 依週期排出來的「什麼時候該保養哪一台」 |
| 保養紀錄 | 實際做完一次保養的紀錄，含日期、執行人、結果 |
| 點檢 | 每天開機前的例行檢查，項目簡單、頻率高 |
| 異常 | 保養過程中發現的問題，例如零件磨損、有異音 |
| 逾期未保養 | 超過應保養日期還沒做。**逾期通常不是儲存的欄位，是把應保養日跟今天比較算出來的** |

**「保養項目」與「保養紀錄」是兩件事。** 前者是「這台設備每次保養要做哪幾項」的規格，後者是「這一次實際做了什麼」的結果。你的資料設計要分得開這兩者。

## 二、為什麼需要一套系統

### 2.1 現在的做法有什麼問題

| 問題 | 具體情況 |
|---|---|
| 沒有人主動提醒 | 保養人員忙起來就忘了，牆上的計畫表不會提醒任何人 |
| 紀錄散在現場 | 每台設備旁邊一張表，要查歷史得一台一台走過去看 |
| 漏做看不出來 | 表上少一個簽名，可能是漏做，也可能是做了忘了簽，事後分不出來 |
| 保養時發現的異常沒有下文 | 寫在表格的備註欄裡，沒有人會再看 |
| 統計不出來 | 說不出這一季的保養達成率是多少 |

### 2.2 系統要解決哪幾件事

1. 每台設備的保養週期與保養項目建檔，不再只存在保養人員的腦袋裡。
2. 隨時列得出哪幾台已逾期、哪幾台這週要保養。
3. 保養做完在系統上登錄，含執行人、日期與結果。
4. 保養時發現的異常能記下來並追蹤有沒有處理。
5. 任一台設備的完整保養履歷都查得到。

## 三、誰會用這套系統

| 角色 | 現場的實際身分 | 在這套系統裡做什麼 | 多久用一次 | 最在意什麼 |
|---|---|---|---|---|
| 操作員 | 產線上操作那台設備的人 | 做日常點檢並登錄、回報設備異常 | 每天 | **每天都要用，所以要快。** 開機前三分鐘做完 |
| 保養人員 | 設備課或保養班人員 | 看待保養清單、登錄保養結果、登記發現的異常 | 每天 | 今天該做哪幾台要一眼看得出來 |
| 主管 | 設備課長、廠長 | 看逾期清單與保養達成率 | 每週 | 有沒有設備長期沒保養 |

**操作員每天用、主管每週用，兩個畫面的設計取向完全不同。** 前者要極簡到不需要思考，後者要能篩選與彙總。

## 四、要管哪些東西

以下用白話列出這套系統要記錄的資訊。**怎麼拆成資料表、每張表有哪些欄位，是你的工作，這裡不給。**

**關於每一台設備**

- 它是什麼（名稱、型號、廠牌）
- 它的編號（廠內唯一）
- 放在哪一條產線、哪個位置
- 目前能不能用

**關於保養的規格**

- 這台設備有哪幾種保養（點檢、月保養、年度保養）
- 每一種的週期是多久
- 每一種要做哪幾個項目
- 由誰負責

**關於每一次實際保養**

- 保養的是哪一台、哪一種保養
- 什麼時候做的
- 誰做的
- 各項目的結果（正常、異常、未執行）
- 有沒有發現異常，異常的描述

**注意這三組資訊的關係。** 一台設備有多種保養規格，一種保養規格會被執行很多次——這是三層結構。**三層之間怎麼關聯、各層有哪些欄位，你要自己決定。**

## 五、一次保養的一生

```text
依保養規格產生應保養的項目（狀態：待保養）
  → 接近應保養日（提醒保養人員）
  → 保養人員執行並登錄結果（狀態：已完成）
  → 過程中發現異常 → 登記異常，狀態為已完成但待追蹤
  → 應保養日過了還沒做（狀態：逾期）
  → 設備停用或報廢 → 之後的保養不再產生（終點）
```

**例外會發生在這幾個地方，設計時都要有答案：**

| 環節 | 例外情況 | 你要決定什麼 |
|---|---|---|
| 到期 | 該保養了，但那條產線正在趕貨不能停機 | 可以延期嗎？延期要不要人核准、要不要留紀錄？ |
| 執行 | 這次保養只做了五項中的三項 | 算完成還是未完成？沒做的三項怎麼記？ |
| 逾期 | 上一次逾期二十天才做 | 下一次的應保養日從「原訂日」還是「實際保養日」開始算？ |
| 提前 | 設備要大修，順便提前保養 | 提前做了，這一次的週期怎麼重算？ |
| 異常 | 保養時發現軸承要換，但零件要等三天 | 這次保養算完成嗎？異常怎麼追？ |

**「上一次逾期了，下一次從哪天算起」這一條是本題的核心**，它直接引出第六節的取捨。

## 六、這一題要想清楚的地方

### 6.1 問題在哪

畫面上一定要顯示「下次應保養日」，因為那是整套系統的用途所在。

**問題是這個日期怎麼來。** 直覺的答案是「上次保養日 ＋ 保養週期」，但只要有一次逾期，這個算式就會出現兩種答案。

一台設備週期 30 天，原訂 3 月 1 日保養，結果拖到 3 月 20 日才做。下一次是 3 月 31 日（原訂日 ＋ 30 天），還是 4 月 19 日（實際保養日 ＋ 30 天）？

### 6.2 兩種做法，各自的代價

**做法 A：從原訂日往後推（固定行事曆）**

| | |
|---|---|
| 好處 | 保養日期固定，年度計畫排得出來，主管好安排人力 |
| 代價 | **逾期會累積。** 這次拖了 19 天，下一次只剩 11 天就到期，現場會覺得系統一直在催 |
| 適合什麼 | 有法規或客戶要求「一年幾次」的設備 |

**做法 B：從實際保養日往後推（浮動週期）**

| | |
|---|---|
| 好處 | 兩次保養之間永遠間隔 30 天，符合「保養是為了設備狀況」的本意 |
| 代價 | **日期會一路往後漂。** 每次都晚幾天，一年下來可能少做一次 |
| 額外問題 | 年度保養計畫排不出來，因為未來的日期取決於實際執行 |

### 6.3 不管選哪一種，還有一個問題

**沒做的那一次要不要留下來？**

| 選項 | 好處 | 代價 |
|---|---|---|
| 不留，逾期就直接把應保養日往後推 | 資料乾淨 | 查不出「這台今年漏做了兩次」，達成率算不出來 |
| 留下來，標記為逾期或未執行 | 統計得出達成率，稽核查得到 | 資料表要能容納「應該發生但沒發生」的紀錄，設計會多一層 |

第二個選項比第一個難，但它是這一題真正的價值所在：**保養系統要記錄的不只是做了什麼，還有該做而沒做的。**

### 6.4 這一題會逼你回答什麼

期末第 4 項〈資料設計〉要求你交一張**畫面欄位對照表**。這一題的關鍵欄位是「下次應保養日」——它是存在資料表裡的欄位，還是每次算出來的？如果是算出來的，算式是什麼、遇到逾期時怎麼處理？

能把這件事寫清楚，代表你理解了「規則要放在資料裡還是放在程式裡」這個問題。這是本題最主要的學習點，也是訪談一定會問的地方。

**要選 A 還是 B、要不要留下未執行的紀錄，你自己決定，理由要寫進第 8 項的設計決策紀錄。**

## 七、容易走偏的方向

| 走偏的做法 | 為什麼不對 |
|---|---|
| 把故障報修也做進來 | 那是另一題。本題只做預防保養，**壞了才修不在範圍內** |
| 保養紀錄併進設備主檔，只留最後一次 | 查不出履歷，這是本題最嚴重的錯誤 |
| 做成依設備狀況自動決定保養時機（預測保養） | 那需要感測器與演算法，會變成另一個領域的專題 |
| 只做提醒，不做紀錄 | 提醒了但沒有人登錄結果，系統就只是一個鬧鐘 |
| 保養項目寫死在程式裡 | 每台設備的項目不同，而且會調整。這件事要放在資料裡 |
| 忽略「保養時發現的異常」 | 那是保養最有價值的產出之一，漏掉它系統只剩打勾功能 |

## 八、第一週建議做什麼

1. **去找一張真的保養表。** Google「設備保養紀錄表 範本」「預防保養計畫表」找得到大量實例。系上實驗室的儀器旁邊可能也貼著一張。把每一個欄位抄下來，逐一問：這一欄是誰填的？填了給誰看？
2. **找一位實習過設備或製造的學長姐問十分鐘**：保養怎麼排、忘記做的時候怎麼辦。
3. **列出三種不同的設備，查它們的建議保養週期。** 你會發現同一台設備有好幾種週期，這件事會直接影響你的資料設計。
4. **決定第六節那個取捨**（下次保養日怎麼算、未執行要不要留），把理由寫成三句話。這三句話會直接進第 8 項的設計決策紀錄。

第 4 步最重要。**這個決定做完，這一題有一半就想通了。**
