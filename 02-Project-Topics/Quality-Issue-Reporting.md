# 品質異常回報管理系統

> **領域**：品質管理｜**難度**：入門｜**這一題要想清楚的問題**：「處理完了」跟「可以結案了」不是同一件事，誰有權說結案？
>
> 五題共通的名詞見本資料夾的[期末設計題目說明](README.md)〈五〉。

---

## 一、先看懂這件事在說什麼

### 1.1 一個你已經懂的類比

你在網路上買的東西收到時破了，於是拍照回報給客服。客服看了照片，把案子轉給倉儲部門查原因，倉儲回覆說是包裝方式有問題，客服再回頭通知你已經改善、案子結束。

**工廠的品質異常回報就是同一條路徑**：現場有人發現不對勁 → 回報 → 有人被指派去處理 → 處理完回報結果 → 有人確認可以結案。

### 1.2 現場實際長什麼樣

作業員在產線上發現問題：這批零件的孔位偏了、表面有刮痕、尺寸量起來不對、機台開始出現異音導致產品不穩。

這些狀況都需要有人處理，但作業員自己處理不了——他不知道原因，也沒有權限決定這批貨要報廢還是重工。他能做的是**把事情講出來，讓對的人來看**。

一間中小型工廠的實際狀況大致是這樣：

| 面向 | 現況 |
|---|---|
| 怎麼回報 | 喊班長，班長打電話給品管，或是填一張紙本的異常單 |
| 誰處理 | 品管人員判定，必要時找製造、模具或設備的人一起看 |
| 怎麼追 | **靠記憶跟催。** 品管人員自己記得有哪幾件還沒處理完 |
| 結果去哪 | 紙本歸檔在資料夾裡，幾乎不會有人再翻開 |

出問題通常是在同一個異常又發生的時候：

> 「這個孔位偏移上個月不是就發生過了嗎？當時怎麼處理的？」
> 「有處理啊……單子應該在櫃子裡，我找找看。」

### 1.3 名詞解釋

| 名詞 | 意思 |
|---|---|
| 品質異常 | 產品、材料或製程出現不符合標準的狀況 |
| 異常單（異常回報單） | 一次異常的完整紀錄，從發現到結案都在同一張單上 |
| 回報人 | 發現異常並登記的人，通常是現場作業員 |
| 責任單位 | 被指派要處理這件異常的部門，例如品管、製造、設備、採購 |
| 處理對策 | 針對這次異常實際做了什麼，例如全數挑選、退回供應商、調整機台參數 |
| 暫時對策與長期對策 | 暫時對策是先讓產線動起來，長期對策是讓它不要再發生。**兩者是不同的欄位** |
| 結案 | 確認對策有效、這件異常不再追蹤 |
| 附件 | 佐證用的照片或量測資料。**現場異常最有用的證據往往是一張照片** |
| 影響範圍 | 這次異常牽涉到多少數量、哪一批、有沒有已經出貨 |

**「處理完」與「結案」是兩件事**，這一點很多人第一次接觸會混掉。處理的人說「我調好了」，但那批已經做出來的東西怎麼辦、會不會再發生，要由回報端或品管確認。你的流程設計要分得開這兩個動作。

## 二、為什麼需要一套系統

### 2.1 現在的做法有什麼問題

| 問題 | 具體情況 |
|---|---|
| 回報成本高 | 要找到班長、班長要找到品管，找不到人就先放著 |
| 沒有人知道進度 | 回報的人回報完就沒下文了，不知道有沒有人在處理 |
| 案子會消失 | 品管人員請假，他記在腦袋裡的那幾件就停住了 |
| 查不到歷史 | 同樣的問題再發生，找不到上次怎麼處理的 |
| 統計不出來 | 說不出這個月最常發生的異常是哪一類，改善沒有依據 |

### 2.2 系統要解決哪幾件事

1. 現場能在一兩分鐘內完成回報，含拍照。
2. 每一件異常都指派得出責任單位，並看得到目前處理到哪一步。
3. 未結案的異常隨時列得出來，不靠任何人的記憶。
4. 每一件異常從發現到結案的完整過程都查得到。
5. 能依異常類別、產品、責任單位統計次數。

## 三、誰會用這套系統

| 角色 | 現場的實際身分 | 在這套系統裡做什麼 | 多久用一次 | 最在意什麼 |
|---|---|---|---|---|
| 回報人 | 產線作業員、班長 | 登記異常、上傳照片、看自己回報的案子處理到哪 | 每週一兩次 | **要快而且要簡單。** 站在機台旁邊、手上有事，填太多欄位他就不填了 |
| 品管人員 | 品保或品管課人員 | 判定類別、指派責任單位、登記處理結果、結案 | 每天 | 不要漏掉任何一件；同類異常要查得到前例 |
| 主管 | 品保主管、廠長 | 看未結案清單與統計、催辦逾期案件 | 每週 | 有沒有案子卡住太久；哪一類問題重複發生 |

**「回報人最在意什麼」這一欄會直接推翻設計。** 回報畫面如果要填十個欄位、要選三層下拉選單，作業員就會回去用喊的，這套系統等於白做。

## 四、要管哪些東西

以下用白話列出這套系統要記錄的資訊。**怎麼拆成資料表、每張表有哪些欄位，是你的工作，這裡不給。**

**關於每一件異常**

- 誰在什麼時候發現的
- 發生在哪裡（產線、工站、機台）
- 是哪個產品、哪一批
- 異常的描述
- 異常的分類
- 影響的數量
- 目前處理到哪一步
- 附上的照片

**關於處理的過程**

- 指派給哪個單位、指派的人是誰、什麼時候指派的
- 做了什麼處理
- 誰處理的、什麼時候處理完
- 結案的人是誰、什麼時候結案、結案的說明

**注意這兩組資訊的關係。** 一件異常可能被轉手好幾次：先派給製造，製造查出是材料問題再轉給採購。你要決定**只記最後一手，還是把每一次轉手都留下來**——這個決定會直接改變你的資料表結構。

## 五、一張異常單的一生

```text
現場發現異常
  → 登記異常單（狀態：待處理）
  → 品管判定類別、指派責任單位（狀態：處理中）
  → 責任單位登記處理對策與結果（狀態：待確認）
  → 品管或回報人確認有效 → 結案（終點）
                        └→ 確認無效 → 退回，回到「處理中」
  → 判定不成立（誤報）→ 直接結案並註明理由（終點）
```

**例外會發生在這幾個地方，設計時都要有答案：**

| 環節 | 例外情況 | 你要決定什麼 |
|---|---|---|
| 登記 | 同一件事被兩個班的人各回報一次 | 要不要合併？怎麼認得出是同一件？ |
| 指派 | 責任單位收到後說「這不是我們的問題」 | 可以退回嗎？退回之後由誰重新指派？ |
| 處理 | 處理完成但是治標不治本 | 暫時對策與長期對策要不要分開登記？ |
| 確認 | 沒有人來確認，案子停在待確認 | 停多久算逾期？逾期要通知誰？ |
| 結案 | 回報人已經離職或調班 | 誰有權代替他確認？ |

**「責任單位說這不是我們的問題」這一條特別值得處理。** 它在現實中天天發生，而且它會讓你的狀態機多出一條往回走的路徑——這種轉移最容易在設計時被漏掉。

## 六、這一題要想清楚的地方

### 6.1 問題在哪

異常單有一個狀態欄位，其中兩個值很像：「待確認」與「已結案」。

責任單位登記完處理對策，他認為自己做完了。但這件異常能不能結案，不是由他決定的——對策有沒有效、那批貨怎麼處理，要由品管或回報人確認。

**於是問題變成：這兩個動作要不要分成兩步？**

### 6.2 兩種做法，各自的代價

**做法 A：處理完就結案，由責任單位一次完成**

| | |
|---|---|
| 好處 | 流程短，兩個動作變一個，使用者少一次操作 |
| 代價 | **處理的人替自己打分數。** 對策有沒有效沒有人確認，異常會重複發生 |
| 現場會怎樣 | 統計上看起來每件都結案了，但同一類異常每個月都在出現 |

**做法 B：處理與結案分開，由不同的人執行**

| | |
|---|---|
| 好處 | 有人替對策的有效性把關，退回的機制也才有地方放 |
| 代價 | 多一個角色、多一個狀態、多一次操作。**確認的人不做事，案子就會卡住** |
| 額外問題 | 「誰有權確認」要定義清楚：回報人？品管？還是兩者都可以？ |

### 6.3 選了 B 之後還有一個問題

案子卡在「待確認」太久怎麼辦？

| 選項 | 好處 | 代價 |
|---|---|---|
| 不處理，靠主管自己看清單 | 最簡單 | 沒人看就永遠卡著 |
| 超過幾天自動結案 | 清單會乾淨 | **等於沒有確認**，做法 B 的意義消失 |
| 超過幾天在清單上標紅並通知主管 | 卡住的案子看得見 | 要多一個「幾天算逾期」的規則要放在某處 |

### 6.4 這一題會逼你回答什麼

期末第 3 項要求你畫活動圖與狀態機圖。這一題的價值就在那條**退回的箭頭**：確認不通過時，狀態要回到哪裡、原本的處理紀錄要不要留著、誰會收到通知。

能把這條路徑畫完整，代表你理解了「流程不是一條直線」。這是本題最主要的學習點，也是訪談一定會問的地方。

**要選 A 還是 B，你自己決定，理由要寫進第 8 項的設計決策紀錄。**

## 七、容易走偏的方向

| 走偏的做法 | 為什麼不對 |
|---|---|
| 回報畫面塞十幾個必填欄位 | 作業員不會填。**回報的門檻越低，系統才越有資料** |
| 只有一個狀態欄位，沒有處理過程的紀錄 | 查不出「這件案子被轉了幾手、每一手做了什麼」 |
| 做成 AI 影像自動判定不良 | 這會變成影像辨識專題，超出本課程範圍 |
| 做成完整的 8D 報告或矯正預防措施系統 | 範圍會爆掉。本題到「登記對策與結案」為止 |
| 把不良品的後續處理（重工、報廢、挑選）也做進來 | 那是另一套系統。本題只記「這件異常怎麼處理的」 |
| 忽略照片 | 現場異常最有用的證據就是照片，漏掉它系統的價值少一半 |

## 八、第一週建議做什麼

1. **去找一張真的異常單。** Google「品質異常單 範本」「異常處理單」找得到大量實例。把上面每一個欄位抄下來，逐一問：這一欄是誰填的？在哪一步填？
2. **找一位實習過品保或製造的學長姐問十分鐘**：異常怎麼回報、最常卡在哪一步。
3. **把第五節那張例外表裡你答不出來的問題圈出來。**
4. **決定第六節那個取捨**（處理與結案要不要分開），把理由寫成三句話。這三句話會直接進第 8 項的設計決策紀錄。

第 4 步最重要。**這個決定做完，這一題有一半就想通了。**
