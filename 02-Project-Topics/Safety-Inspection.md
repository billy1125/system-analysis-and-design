# 工安巡檢與缺失追蹤系統

> **領域**：工業安全｜**難度**：入門｜**這一題真正要想的問題**：限期改善的天數怎麼定、逾期要升級到哪一層
>
> 五題共通的名詞見本資料夾的[期末設計題目說明](README.md)〈五〉。

---

## 一、先看懂這件事在說什麼

### 1.1 一個你已經懂的類比

學校每學期會有實驗室安全檢查。有人拿著一張表單走一圈，看滅火器有沒有過期、逃生門有沒有被雜物堵住、化學品有沒有分類存放。發現問題就寫在表單上，要求負責的老師或助教在某一天之前改好，之後再回來確認有沒有改。

**工廠的工安巡檢就是同一件事，只是規模更大、後果更嚴重。** 學校實驗室出事可能是一個人受傷，工廠一條產線出事可能是十幾個人。

### 1.2 現場實際長什麼樣

工安人員（通常是職業安全衛生管理員）依照排定的頻率，帶著巡檢表走過指定區域。

**巡檢表上的項目大致是這幾類：**

| 類別 | 檢查項目舉例 |
|---|---|
| 消防 | 滅火器壓力是否正常、是否過期、消防栓前是否被擋住 |
| 通道與逃生 | 逃生通道是否堆放物品、逃生標示是否亮著、堆高機通道是否淨空 |
| 機械安全 | 機台安全護罩是否拆除、緊急停止按鈕是否有效、旋轉部位是否加蓋 |
| 電氣 | 電線是否裸露、配電箱是否上鎖、插座是否過載 |
| 環境 | 地面是否有油污積水、照明是否足夠、噪音區域是否標示 |
| 人員 | 個人防護具是否穿戴（安全鞋、護目鏡、耳塞、手套） |
| 化學品 | 是否標示、是否分類存放、是否有安全資料表 |

發現不符合的項目就是一條**缺失**。每條缺失要指定責任單位、寫下限期改善的日期。責任單位改善完成後，工安人員要回去**複查**，複查通過才能關閉這條缺失。

**現在的做法：**

| 面向 | 現況 |
|---|---|
| 巡檢紀錄 | 紙本巡檢表，勾選與手寫 |
| 缺失照片 | 用手機拍，存在自己的相簿裡 |
| 缺失追蹤 | 一本 Excel，每條缺失一列，改善完成後把該列標綠色 |
| 通知責任單位 | 通訊軟體群組，或每週的工安會議上口頭宣布 |
| 逾期處理 | 每週會議上把未結案的清單念一遍 |

出問題通常是這樣：三個月後同一個地方又被檢出同一條缺失，但沒有人記得上次也檢出過、上次是誰負責、上次是怎麼改的。

### 1.3 名詞解釋

| 名詞 | 意思 |
|---|---|
| 巡檢（稽查） | 依排定頻率到現場逐項檢查是否符合規定 |
| 巡檢表（檢查表） | 列出所有要檢查的項目的表單。同一種區域用同一份巡檢表 |
| 檢查項目 | 巡檢表上的單一項目，例如「滅火器壓力是否正常」。**項目會隨法規與現場狀況調整** |
| 缺失（不符合事項） | 檢查發現不符合規定的情況。一次巡檢可能產生零條到很多條 |
| 責任單位 | 被指派要改善這條缺失的部門或人 |
| 限期改善 | 要求在某一天之前完成改善 |
| 複查 | 責任單位回報改善完成後，由原巡檢人員回到現場確認 |
| 關閉（結案） | 複查通過，這條缺失處理完畢 |
| 升級 | 逾期未改善時，通報給更高層級的主管。層級越高壓力越大 |
| 風險等級 | 缺失的嚴重程度分級，常見為高、中、低。**等級不同，處理的急迫性也不同** |
| 個人防護具（PPE，Personal Protective Equipment） | 安全帽、安全鞋、護目鏡、耳塞、手套、口罩等保護穿戴 |
| 安全資料表（SDS，Safety Data Sheet） | 化學品的危害與處理說明文件，法規要求必須在現場備置 |
| 職業安全衛生法 | 台灣規範工作場所安全的主要法律，要求事業單位定期實施自動檢查 |

**「缺失」與「巡檢」是兩層資料**，這一點要先分清楚。一次巡檢是一個事件（誰、什麼時候、檢查了哪個區域、檢查了哪些項目），缺失是這個事件的產出（發現了幾條問題）。一次巡檢可能零缺失，也可能十條缺失。這是本題主檔與明細的分界。

## 二、為什麼需要一套系統

### 2.1 現在的做法有什麼問題

| 問題 | 具體情況 |
|---|---|
| 照片與紀錄對不起來 | 缺失寫在紙上，照片在手機裡，兩者靠記憶連結 |
| 逾期沒有人盯 | 要等每週會議才會發現某條缺失已經逾期兩週 |
| 反覆發生看不出來 | 同一個地點、同一個項目每季都被檢出，但沒有資料可以證明 |
| 責任單位說沒收到 | 通訊軟體訊息被洗掉，沒有人能證明通知過 |
| 複查常被漏掉 | 責任單位說改好了，就被當成結案，沒有人真的去看 |
| 巡檢項目版本混亂 | 法規修改後巡檢表更新，但舊的紙本還在用 |

### 2.2 系統要解決哪幾件事

1. 巡檢紀錄與缺失、照片綁在一起，查得出來。
2. 逾期的缺失自動看得出來，不必等會議。
3. 同一地點、同一項目的重複缺失查得出歷史。
4. 責任單位收到指派這件事有紀錄。
5. 複查是關閉缺失的必要條件，不能跳過。

## 三、誰會用這套系統

| 角色 | 現場的實際身分 | 在這套系統裡做什麼 | 多久用一次 | 最在意什麼 |
|---|---|---|---|---|
| 巡檢人員 | 職業安全衛生管理員、工安專員 | 執行巡檢、逐項勾選、開立缺失、上傳照片、執行複查 | 每週數次 | 現場登錄要快，站在產線旁邊用手機或平板就能填完 |
| 責任單位承辦 | 產線班長、課長、設備人員 | 看指派給自己的缺失、回報改善完成 | 被指派時 | 不要一直被催；限期要合理，有些改善需要採購或停機 |
| 工安主管 | 工安課長、廠務經理 | 看逾期清單、看重複發生的缺失、應對主管機關檢查 | 每週一次 | 不要有逾期很久還沒處理的高風險缺失 |

**巡檢人員是在現場站著操作的**，這一點會直接影響介面設計：他可能戴著手套、拿著平板、周圍很吵。這是期末第 6 項〈使用者介面原型〉要求考慮「工業現場操作限制」的實際案例，這一題可以寫得很具體。

## 四、要管哪些東西

以下用白話列出，**怎麼拆成資料表、每張表有哪些欄位是你的工作，這裡不給。**

**關於巡檢的設定**

- 有哪些區域要巡檢（廠區、產線、倉庫、實驗室）
- 每個區域多久巡檢一次
- 巡檢表上有哪些檢查項目，各屬於哪一類
- 每個項目的風險等級

**關於每一次巡檢**

- 檢查的是哪個區域
- 誰檢查的、什麼時候
- 每一個項目的結果（符合、不符合、不適用）

**關於每一條缺失**

- 是哪一次巡檢、哪一個項目發現的
- 具體情況的文字描述與照片
- 風險等級
- 指派給哪個責任單位、哪一個人
- 限期改善日
- 責任單位回報的改善內容與完成日
- 複查結果與複查人、複查日
- 目前處理到哪裡

**注意「不適用」這個結果。** 巡檢表上的某個項目，在某個區域可能根本不存在（例如倉庫沒有機台護罩）。設計時要決定：這種情況是勾「符合」、勾「不適用」，還是這個區域的巡檢表本來就不該有這個項目？三種做法的資料設計完全不同。

## 五、一張單子的一生

這一題有**兩張單子**，生命週期不同，這是它跟其他題目最大的差別。

**巡檢單的一生（短，通常一天內走完）**

```text
排定或臨時建立
  → 巡檢中（逐項勾選）
  → 完成（產生 0 到多條缺失）
  → 結束
```

**缺失的一生（長，可能拖好幾個月）**

```text
開立（附照片、指定責任單位與限期）
  → 限期改善中
  → 責任單位回報改善完成 → 待複查
  → 複查通過 → 關閉（終點）
  → 複查不通過 → 退回，重新指定限期 → 回到「限期改善中」
  → 超過限期仍未改善 → 逾期（升級通報）
```

**例外會發生在這幾個地方，設計時都要有答案：**

| 環節 | 例外情況 | 你要決定什麼 |
|---|---|---|
| 指派 | 責任單位認為這不是自己的責任 | 要不要有「退回爭議」的機制？誰來裁決？ |
| 限期改善 | 改善需要採購設備或停線，做不到限期 | 允許展延嗎？展延要誰核准？展延過的算不算逾期？ |
| 複查 | 第二次複查還是不通過 | 要不要升級？重新限期的天數跟第一次一樣嗎？ |
| 巡檢 | 巡檢當天該區域停工，進不去 | 這次巡檢算做了還是沒做？沒做要不要補？ |
| 逾期 | 逾期兩個月了還沒改 | 升級到哪一層？升一次就停，還是每逾期一週再升一層？ |
| 人員異動 | 責任單位的承辦人離職了 | 缺失轉給誰？ |

**「展延」這一條最容易被漏掉，卻在現實中最常發生。** 一條需要買設備才能改善的缺失，限期三天必然做不到。你的設計要嘛允許展延，要嘛在開立時就依風險等級給不同天數——但不能假裝這件事不存在。

## 六、這一題的設計難點

### 6.1 問題在哪

「限期改善」聽起來很簡單：開立日加幾天。但真的要填進資料字典的值域欄時，你會發現四個問題全部沒有答案。

### 6.2 四個要決定的問題

**問題一：限期天數怎麼定？**

| 做法 | 好處 | 代價 |
|---|---|---|
| 全部一樣，例如開立日加 7 天 | 最簡單，規則好懂 | **不合理。** 「地面有油污」可以當天清掉，「機台護罩被拆除要重新製作」要兩週。同樣給 7 天，一個太鬆一個太緊 |
| 依風險等級決定（高 3 天、中 7 天、低 30 天） | 合理，反映急迫性 | 要多一份「風險等級對應天數」的設定資料；而且風險等級由誰判定？ |
| 開立時由巡檢人員逐條填 | 最靈活 | 同一種缺失不同人給不同天數，缺乏一致性 |

**問題二：假日算不算？**

「限期 3 天」，如果星期五開立，到期日是星期一還是星期三？遇到連假呢？

| 做法 | 代價 |
|---|---|
| 算日曆天（直接加 3 天） | 簡單，但遇到連假時實際只有一個工作日可以處理 |
| 算工作日 | 合理，但系統要知道哪些天是假日——**這需要一份行事曆資料**，而且每年要維護 |

**這個決定會改變你的資料表數量。** 選工作日，就多一張假日行事曆表。

**問題三：逾期要升級到哪一層？**

| 做法 | 好處 | 代價 |
|---|---|---|
| 逾期就通報工安主管，一次就好 | 簡單 | 主管收到通報但責任單位還是不改，就沒有下一步了 |
| 逾期每滿一週再升一層（班長 → 課長 → 廠長） | 有壓力遞增的效果 | 需要一份「組織層級」資料，而且要算「現在該升到第幾層」 |

第二種做法會讓你面對一件事：**「目前升級到第幾層」也是算出來的**，就跟「逾期」一樣。

**問題四：規則改了，舊資料怎麼辦？**

假設你設計成「風險等級決定限期天數」，高風險原本是 3 天。半年後主管說改成 2 天。

| 做法 | 代價 |
|---|---|
| 已開立的舊缺失跟著變成 2 天 | 有些原本沒逾期的缺失會突然變成逾期，責任單位會抗議 |
| 舊缺失維持原本的 3 天 | 合理，但**這代表限期日必須在開立當下就算出來存進資料**，不能每次查詢時才用規則算 |

**這一題最深的一層就在這裡。** 前面三個問題你都可以選「不存、每次算」，但第四個問題會逼你把限期日存下來——因為規則會變，而已開立的單據不該被後來的規則追溯改變。

### 6.3 這一題會逼你回答什麼

同一份設計裡，**有些東西該存、有些東西該算，判準是什麼。**

- 限期日：**該存**（因為規則會變，舊單不該被追溯）
- 是否逾期：**該算**（限期日跟今天比較，每天都不一樣）
- 升級層級：**該算**（由逾期天數推出來）

能把這三條講清楚，你就掌握了資料設計裡最實用的一條判準。**這三個判斷你自己做，寫進第 8 項的設計決策紀錄。**

## 七、容易走偏的方向

| 走偏的做法 | 為什麼不對 |
|---|---|
| 把巡檢表的檢查項目寫死在畫面上 | 項目會隨法規與現場改變。項目必須是可維護的資料，不是程式裡的固定清單 |
| 一條缺失只用一個文字欄位記錄 | 追不出「同一地點同一項目重複發生」。缺失必須連得回區域與檢查項目 |
| 不設複查，責任單位回報完成就關閉 | 那就失去追蹤的意義了。複查是這一題的核心環節之一 |
| 只做記錄，不做逾期判定 | 系統退化成電子版的紙本巡檢表，沒有解決任何問題 |
| 忽略展延 | 現實中最常發生的例外。漏掉它，活動圖會少一整條分支 |
| 想做感測器連線、即時告警 | 超出範圍。本題是人工巡檢的記錄與追蹤，不是自動偵測 |
| 把風險等級評估做成計分模型 | 那是風險評估方法論，不是系統設計。等級由巡檢人員選定即可 |
| 把「不適用」當成「符合」處理 | 兩者意義不同，混在一起就算不出真正的符合率 |

## 九、第一週建議做什麼

1. **拿到一份真的巡檢表。** 系上實驗室的安全檢查表，或 Google「工安巡檢表」。把檢查項目全部抄下來，數一數有幾項、分成幾類。
2. **對每一個項目問一次「這條缺失多久能改好」。** 你會發現差距很大，從當天到兩週都有。這就是第六節問題一的材料。
3. **找出一條需要採購或停線才能改善的缺失**，然後回答：限期怎麼給才合理？
4. **決定第六節那四個問題**，特別是第四個（規則改了舊資料怎麼辦）。寫下你的選擇與理由。

第 3 步最能看出你有沒有真的想過。**現實中最麻煩的缺失就是那種「知道要改但改不快」的**，設計時避開它，交出去的東西就不能用。
