# 工具借用與歸還管理系統

> **領域**：生產現場管理｜**難度**：入門｜**這一題要想清楚的問題**：「這支工具現在在誰手上」要存成欄位，還是由借用紀錄推出來？
>
> 五題共通的名詞見本資料夾的[期末設計題目說明](README.md)〈五〉。

---

## 一、先看懂這件事在說什麼

### 1.1 一個你已經懂的類比

圖書館借書。你刷卡把書帶走，系統記下這本書幾號借出、幾號要還；還書時再刷一次，這本書回到書架上可以被下一個人借。逾期會有提醒，書破了要送修，修的期間別人借不到。

**工廠的工具借用就是同一件事，只是借的東西從書變成扭力扳手、電動起子、專用治具。**

### 1.2 現場實際長什麼樣

工廠裡有一批工具是「大家共用」的：貴、用的次數不多、每個人都買一支不划算。常見的有電動起子、扭力扳手、專用治具、拆卸工具、量測用的簡易夾具。

這些東西統一放在工具室或工具櫃，由工具室管理員保管。作業員要用的時候去借，用完拿回來還。

一間中小型工廠的實際狀況大致是這樣：

| 面向 | 現況 |
|---|---|
| 數量 | 幾十件到兩三百件，每一件貼一個編號，例如 `TL-0087` |
| 借用方式 | **一本簿子。** 借的人自己寫下工具編號、姓名、日期，還的時候在後面補一個歸還日期 |
| 誰在管 | 工具室管理員，多半還兼別的工作，不會整天守在那裡 |
| 常見狀況 | 借了忘了還、還了忘了登記、換班時直接傳給下一個人、壞掉先放在角落 |

出問題通常是在急著要用的時候：

> 「三號扭力扳手在哪裡？」
> 「不知道，簿子上寫上禮拜二小陳借的，但他說他早就還了。」

### 1.3 名詞解釋

| 名詞 | 意思 |
|---|---|
| 共用工具 | 不屬於個人、由工具室統一保管、需要時才借出的工具 |
| 工具編號 | 每一件工具的唯一識別碼。**同型號的兩支是兩件不同的工具**，因為要分得出是哪一支壞了 |
| 借出 | 工具離開工具室，交由某位員工保管使用 |
| 歸還 | 工具交回工具室，回到可借用的狀態 |
| 預計歸還日 | 借的時候約定什麼時候要還回來 |
| 逾期 | 超過預計歸還日還沒還。**逾期不是存下來的欄位，是把日期跟今天比較算出來的** |
| 送修 | 工具損壞，送去維修，這段期間不能借給任何人 |
| 報廢 | 修不好或不值得修，正式停用 |
| 保管人 | 目前實際持有這件工具的人 |

## 二、為什麼需要一套系統

### 2.1 現在的做法有什麼問題

| 問題 | 具體情況 |
|---|---|
| 找不到東西 | 要用的時候不知道在誰手上，只能一個一個問 |
| 借還紀錄不完整 | 借的時候寫了，還的時候忘了劃掉，簿子上永遠掛著 |
| 沒有人追逾期 | 借出去三個月沒人發現，因為沒有人會去逐列比對日期 |
| 壞掉的工具照樣被借 | 簿子上看不出這支正在送修 |
| 責任說不清 | 工具壞了，不知道是哪一次借用期間壞的 |

### 2.2 系統要解決哪幾件事

1. 隨時查得到每一件工具目前在哪裡、在誰手上。
2. 借用與歸還都留下紀錄，含時間與人。
3. 逾期未還的清單能主動列出來。
4. 送修中與已報廢的工具不能被借出。
5. 查得到任一件工具的歷次借用紀錄。

## 三、誰會用這套系統

| 角色 | 現場的實際身分 | 在這套系統裡做什麼 | 多久用一次 | 最在意什麼 |
|---|---|---|---|---|
| 借用人 | 產線作業員、維修技術員 | 查工具有沒有人借走、辦借用、辦歸還 | 每週數次 | 借東西不要花時間，站在工具室門口三十秒要辦得完 |
| 工具室管理員 | 工具室或倉庫人員 | 確認借還、登記送修與報廢、追逾期 | 每天 | 東西不要不見；逾期的要看得出來 |

**兩個角色的使用頻率差很多，畫面設計取向也不一樣。** 借用人一次只處理一兩件、要快；管理員一次要看整批、要能篩選與排序。

只有兩個角色是這一題刻意的：角色少，你才有餘裕把借還這條流程的每一個例外都想清楚。

## 四、要管哪些東西

以下用白話列出這套系統要記錄的資訊。**怎麼拆成資料表、每張表有哪些欄位，是你的工作，這裡不給。**

**關於每一件工具**

- 它是什麼（名稱、類型、規格）
- 它的編號（廠內唯一）
- 放在哪個工具櫃或位置
- 目前能不能借

**關於每一次借用**

- 借的是哪一件工具
- 誰借的
- 什麼時候借的
- 預計什麼時候還
- 實際什麼時候還的（還沒還的話這一欄是空的）
- 歸還時工具狀況正不正常

**注意這兩組資訊的關係。** 一件工具會被借很多次，所以借用紀錄不能塞進工具本身——那樣只留得下最後一次，查不出歷史。這是本題主檔與明細的分界，但**兩者各自該有哪些欄位、關聯怎麼建，你要自己決定**。

## 五、一件工具的一生

```text
新購入
  → 建檔，狀態為可借用
  → 被借出（在某人手上）
  → 歸還 ────────────→ 回到「可借用」
  → 歸還時發現損壞 → 送修 → 修好 → 回到「可借用」
                          └→ 修不好 → 報廢（終點）
  → 逾期未還（東西在外面，但已經超過約定日期）
  → 遺失 → 報廢（終點）
```

**例外會發生在這幾個地方，設計時都要有答案：**

| 環節 | 例外情況 | 你要決定什麼 |
|---|---|---|
| 借用 | 這支已經被別人借走了 | 要不要排隊預約？（提示：先想清楚不做預約會怎樣） |
| 借用 | 借的人已經有三件逾期未還 | 系統要擋下他嗎？還是只提醒管理員？ |
| 歸還 | 還回來的人不是當初借的人 | 這樣算不算還了？紀錄上要記誰？ |
| 歸還 | 還回來的時候壞了 | 歸還跟送修是同一個動作還是兩個動作？ |
| 逾期 | 借的人離職了 | 這筆借用紀錄怎麼收尾？ |

**「還回來的人不是當初借的人」這一條特別值得處理。** 現場交接班很常直接把工具傳給下一個人，簿子上完全看不出來。你的設計要嘛承認這件事（記錄轉手），要嘛明確不處理（只認登記的借用人），**但不能假裝它不存在**。

## 六、這一題要想清楚的地方

### 6.1 問題在哪

畫面上你一定會想顯示一欄「狀態」，內容是「可借用」「已借出」「送修中」「已報廢」。

**問題是：「已借出」這個狀態，跟借用紀錄講的是同一件事。** 有一筆借用紀錄還沒填歸還日期，就代表這支在外面；沒有這種紀錄，就代表它在工具室。那還需要在工具主檔上存一個狀態欄位嗎？

### 6.2 兩種做法，各自的代價

**做法 A：工具主檔存一個狀態欄位**

| | |
|---|---|
| 好處 | 查詢最直接。「列出所有可借用的工具」一個條件就查得到 |
| 代價 | **借出與歸還的時候，兩個地方都要改**：寫一筆借用紀錄，同時把工具狀態改掉。漏改一個，兩邊就對不起來 |
| 對不起來會怎樣 | 借用紀錄說這支在小陳手上，工具主檔說它可借用，於是它被借給第二個人 |

**做法 B：不存狀態，每次由借用紀錄推出來**

| | |
|---|---|
| 好處 | **不可能對不起來**，因為只有一份資料 |
| 代價 | 每次查工具清單都要去借用紀錄裡找「有沒有一筆還沒歸還的」，查詢比 A 麻煩 |
| 額外問題 | 「送修中」與「已報廢」不是借用紀錄推得出來的，這兩個還是得存在某個地方。**於是狀態變成一半用算的、一半用存的** |

### 6.3 這一題會逼你回答什麼

期末第 4 項〈資料設計〉要求你交一張**畫面欄位對照表**，回答「這個畫面上的欄位最後存在哪裡」。

工具清單上那一欄「狀態」，你要說得出它的每一個值分別從哪裡來。能寫清楚這件事，就代表你理解了畫面與資料不是一對一的對應——這是本題最主要的學習點，也是訪談一定會問的地方。

**要選 A 還是 B、還是兩者混用，你自己決定，理由要寫進第 8 項的設計決策紀錄。** 三種做法都有人在真實系統裡用。

## 七、容易走偏的方向

| 走偏的做法 | 為什麼不對 |
|---|---|
| 把借用紀錄併進工具主檔，只留最後一次 | 查不出歷史，也就答不出「這支上次是誰用壞的」 |
| 設了狀態欄位卻沒說誰負責更新 | 這就是第六節的核心問題。設計沒有完成 |
| 做成預約排隊與自動配發的最佳化 | 演算法會吃掉整份報告。借不到就等，這是管理問題不是系統問題 |
| 把送修設計成完整的維修工單系統 | 範圍會爆掉。本題只需要記「送修中、什麼時候送的、回來沒」 |
| 加上 RFID 或感測器自動偵測工具進出 | 本題假設是人工登記。要接硬體訊號的一律界外 |
| 只做借還，不處理逾期 | 逾期是這一題最主要的管理價值，做掉了系統就只剩登記簿 |

## 八、第一週建議做什麼

1. **去找一張真的借用登記表。** 系上實驗室、圖書館、器材室都有。把上面每一個欄位抄下來，逐一問：這一欄是誰填的？填了給誰看？
2. **找一位實習過的同學問十分鐘**：你們工具怎麼借、最常出什麼問題。
3. **把第五節那張例外表裡你答不出來的問題圈出來**，那些就是你要去問人的地方。
4. **決定第六節那個取捨**（存狀態或算狀態），把理由寫成三句話。這三句話會直接進第 8 項的設計決策紀錄。

第 4 步最重要。**這個決定做完，這一題有一半就想通了。**
