# 期末設計題目說明

這個資料夾收錄五份題目說明書，供期末小組報告（系統設計）選題與開工使用。

## 一、這些文件在回答什麼

期末的題目是工廠或製造現場的管理系統。大多數同學還沒實習過，光看題目名稱不容易知道那到底在說什麼——「盤點」「預防保養」「異常回報」這些詞在課堂上聽過，但沒有人告訴你現場實際長什麼樣。這五份文件就是要補上這一段。

期末總共有四份文件會用到，分工不重疊：

| 文件 | 回答的問題 | 什麼時候看 |
|---|---|---|
| 本資料夾的五份說明書 | 這個題目在說什麼、現場怎麼運作、名詞是什麼意思 | **選題時與開工前** |
| [報告內容](../00-Course-Introduction/Report-Contents.md)〈二〉 | 必做的八項是什麼（規定的事實來源） | 確認要交什麼 |
| [系統設計範例報告說明](../03-example-reports/Design-Phase-Deliverables.md) | 每一項該有哪些欄位、圖怎麼畫 | 動筆寫某一項卻不知道該放什麼時 |
| [系統設計範例報告](../03-example-reports/Design-Phase-Sample-Report.md) | 交出去的成品長什麼樣 | 想知道整份的長相與詳細程度時 |

後面兩份的示範對象是**工廠訪客進出登記系統**，那是上課帶著大家做的題目，**刻意不在下面五題之中**。你可以照抄它的結構與寫法，但抄不到答案。

選題的判準見〈三〉的五題一覽與〈四〉的使用步驟，不建議做的方向見〈八〉。

## 二、這些文件不會給你什麼

**不給實體關聯圖、不給資料表與欄位、不給模組清單、不給畫面線框。**

那些是你的工作，也是分數所在。這五份給的只有五樣東西：情境、名詞、角色、一張單子（或一件東西）的一生，以及這一題真正要想的問題。

每一份的第六節〈這一題要想清楚的地方〉會把核心取捨攤開——兩種做法各自的好處與代價都寫出來，但**不告訴你該選哪一個**。那一條選擇與理由，就是期末第 8 項〈設計決策紀錄〉裡真正屬於你的內容。照抄不來，也問不到標準答案。

## 三、五個題目一覽

| 說明書 | 題目 | 領域 | 難度 | 這一題要想清楚的問題 |
|---|---|---|---|---|
| [工具借用與歸還管理系統](Tool-Loan-and-Return.md) | 管理工廠共用工具的借出、歸還、逾期與維修狀態 | 生產現場管理 | 入門 | 「這支工具在誰手上」要存成欄位，還是由借用紀錄推出來 |
| [品質異常回報管理系統](Quality-Issue-Reporting.md) | 現場發現異常後通報、指派、處理、結案 | 品質管理 | 入門 | 「處理完了」跟「可以結案了」不是同一件事 |
| [倉庫盤點管理系統](Inventory-Stocktaking.md) | 定期比對帳面庫存與實際數量，處理差異 | 物料與倉儲 | 標準 | 盤點期間帳面還在變，比對的基準要不要凍結 |
| [設備保養紀錄管理系統](Equipment-Maintenance.md) | 依週期排定設備保養、登錄結果、追蹤逾期 | 設備維護 | 標準 | 「下次應保養日」是算出來的還是填出來的 |
| [員工教育訓練紀錄系統](Training-Records.md) | 管理課程、報名、簽到、完訓與應受訓清單 | 人力資源與工安 | 標準 | 報名、簽到、完成是三件事，一個欄位裝不下 |

五題的領域各不相同，要想的問題也刻意錯開，因此不會有兩組交出結構相同的報告。

難度只反映「要想的事情有幾層」，不反映分數上限。**入門題做得深，分數會高過標準題做得淺。**

**五題共同的性質**：單一管理流程、兩到三個角色、五到八個核心功能。這個規模是刻意控制的——它剛好足夠讓你完整走過需求、流程、資料、介面與架構設計，又不會膨脹成 MES、MRP、ERP 這種大型系統。

## 四、怎麼用這五份文件

| 步驟 | 做什麼 |
|:--:|---|
| 1 | 五份的第一節都先讀過。那一節在講「現場長什麼樣」，讀完你才判斷得出哪一題想像得出來 |
| 2 | 挑兩三題，讀它們的第六節。要想的問題看得懂、覺得有東西可想的，才是適合你們的題目 |
| 3 | 選定後，把第三節的名詞表整份看完。**名詞沒弄懂就動筆，寫出來的東西會自己矛盾** |
| 4 | 依第八節做完第一週的準備，再回頭讀[系統設計範例報告說明](../03-example-reports/Design-Phase-Deliverables.md)開始寫 |

第 2 步不要跳過。挑一個「聽起來很酷但完全想不出現場」的題目，八週會非常痛苦。

## 五、五題共通的名詞

各題自己的專有名詞寫在該題的第一節，這裡只放五題都會出現的。

| 名詞 | 意思 |
|---|---|
| 現場 | 工廠裡實際生產的區域，與辦公室相對。「現場人員」指在產線上工作的人 |
| 單據（表單） | 一次作業的紀錄憑證，例如借用單、異常單、盤點單。紙本時代是一張紙，系統化之後是資料庫裡的一筆紀錄 |
| 主檔與明細 | 一張單據常拆成兩層：主檔記「這是誰在什麼時候開的哪一種單」，明細記「這張單包含哪幾個項目、各多少」。盤點單／盤點明細、課程／梯次都是這個結構 |
| 開立 | 建立一張新單據 |
| 簽核（核准） | 由具權限的人確認同意，單據才能往下走。核准的人通常不是開單的人 |
| 結案 | 一張單據完成所有處理，不再變動。什麼條件算結案，往往不是一個動作而是一組條件 |
| 狀態 | 一張單據或一件東西目前走到哪一步。**狀態值有幾個、怎麼轉移，是設計出來的，不是天生的** |
| 逾期 | 超過應完成的期限。**逾期通常不是一個儲存的欄位，而是把期限與今天比較算出來的** |
| 責任單位 | 被指派要處理某件事的部門或人 |
| 料號 | 每一種物料或零件的唯一編號。同一種東西不同規格是不同料號 |
| 帳面與實際 | 帳面是系統或帳冊上的數字，實際是現場真的有多少。兩者不符是製造業最常見的問題之一 |
| 追溯 | 事後查得出「這件事是誰、在什麼時候、怎麼做的」。稽核與客戶抱怨處理都靠它 |

## 六、選定題目之後的第一週

每份說明書的第八節都有針對該題的具體動作，這裡只講三件通用的。

**一、去找一張真的單子。** 五題全部都有紙本或 Excel 的現行做法。Google「借用登記表 範本」「盤點表 範本」「保養紀錄表 範本」找得到大量實例，把上面每一個欄位抄下來。**抄下來的欄位不是答案，是題目**——你要問的是「這一欄為什麼存在、誰填、填了給誰看」，答不出來的欄位就是要去問人的地方。

**二、找一位實習過的人問十分鐘。** 系上大三大四有實習過的學長姐、或修過相關課程的同學。問三個問題就夠了：這件事現在怎麼做、最常出錯的是哪一步、你覺得最麻煩的是什麼。這十分鐘的價值高過查一整天資料。

**三、把第六節那個取捨用自己的話重寫一次。** 寫不出來就是還沒懂。這一步做完，你的第 1 項〈設計基礎與需求摘要〉就有一半的材料了。

## 七、如果讀完還是不懂

**這是正常的，不是你的問題。** 這些題目描述的是你還沒進去過的職場，看不懂的地方一定有。處理順序建議如下：

| 順序 | 做什麼 |
|:--:|---|
| 1 | 把不懂的地方寫成具體問題。「我不懂盤點」問不出東西，「盤點的時候倉庫還在出貨，那數字要怎麼算」才問得出東西 |
| 2 | 問修過相關課程的老師或實習過的同學。工管系的老師對這些現場流程都熟 |
| 3 | 上課問。這五題都是老師選出來的，可以直接問 |
| 4 | 問 AI 幫你梳理概念。但**你必須看懂它給你的東西**，採用之前要能自己說明——懂或不懂，會在口頭報告與個人訪談的問答裡直接顯現出來。使用揭露義務見[SAD 課程介紹](../00-Course-Introduction/Course-Introduction.md)〈AI 工具使用揭露〉 |

**不要用「先寫下去再說」處理看不懂的部分。** 名詞理解錯了，後面八項會一路錯到底，而且訪談時一問就出來。

## 八、有幾件事這五題都不要做

不管你選哪一題，下面這些方向都會讓報告偏離「系統分析與設計」，變成演算法或領域專業的專題：

| 不要做 | 為什麼 |
|---|---|
| 最佳化排程、需求預測、自動補貨演算法 | 演算法本身會吃掉整份報告，而課程要評的是設計能力 |
| 影像辨識、AI 自動判定 | 那是另一個領域，而且你無法在報告裡說明它怎麼運作 |
| 複雜成本分析、財務模型 | 可行性分析只要求說得出主要成本與效益來源 |
| 與 ERP、MES 全面整合 | 介接一到兩條資料就夠了，全面整合會讓範圍失控 |
| 接感測器、RFID、PLC 等硬體訊號 | 五題都假設資料由人工登記。要接硬體的一律界外 |
