# 工單分派管理系統：修改需求提案書

> 老師提供一套已經在使用的[工單分派管理系統](../SAD-Work-Order/README.md)，現在工廠提出兩項新需求。請先操作系統、讀懂它現在怎麼運作，再想清楚系統要怎麼改，寫成期末報告。

---

## 一、系統現況

某中型自行車零件加工廠的生管課，在 2026-10-01 用這套系統取代紙本工單：生管人員開立工單、派給工作中心，組長在系統上回報開工與完工，完工時填良品數與不良數。

| 項目 | 現況 |
|---|---|
| 使用者 | 生管課的人員與各工作中心的組長。作業員不使用這套系統 |
| 使用地點 | 系統裝在生管課的一台電腦，生管辦公室與各工作中心的電腦以瀏覽器連線 |
| 規模 | 8 個畫面、4 張資料表、2 種角色 |
| 主要功能 | 未完工工單清單、開立工單、派工與改派、回報開工與完工、取消工單、工單查詢、產品與工作中心維護、帳號維護 |

## 二、兩項修改需求

| 編號 | 需求 | 提出者 | 一句話說明要解決的問題 |
|---|---|---|---|
| CR-01 | 停工與恢復紀錄 | 生管課長 | 生產中的工單停下來時，系統上看不出來，也不知道停了多久、為什麼停 |
| CR-02 | 分批報工與工時 | 廠長 | 生產中看不到做了多少，完工時只有一個總數，也不知道花了多少工時 |

CR 是 Change Request（變更申請）的縮寫，實務上每一項系統修改都會編一個號碼，方便後續追蹤。

這兩項都是**新的需求**，不是修正錯誤。現行系統運作正常，只是當初沒有納入這些範圍。

---

## 三、CR-01 停工與恢復紀錄

### 3.1 原有系統的缺點

| 缺點 | 現場發生什麼事 |
|---|---|
| 工單停下來，系統上看不出來 | 待料、機台故障或等品檢時，工單在系統上仍是「生產中」。生管人員以為還在做，要到現場才知道停了 |
| 不知道停了多久 | 停工與恢復的時間沒有紀錄。交期延誤時，說不出時間耗在哪裡 |
| 停工原因沒有地方記 | 原因只留在組長的口頭轉述或完工說明裡。想知道最常因為什麼停，只能一張一張問 |
| 停工的單混在生產中的單裡 | 未完工清單上看不出哪幾張停著，生管人員不知道該先去處理哪一張 |

用生管人員的帳號登入，打開未完工清單上的 WO-261030-01：10-31 開工，交期 11-04 已經逾期，畫面上只有「生產中」三個字，看不出它是還在做，還是停著在等什麼。生產中的工單在生管人員的畫面上沒有任何按鈕，連備註都改不了；組長的畫面上也只有「完工回報」。再到「工單查詢」打開 WO-261012-01：預定 10-14 生產，10-16 才開工，10-22 完工，比交期晚 2 天。為什麼晚開工、中間停了多久，只寫在完工備註這段文字裡，而且要等完工才寫得進去。

### 3.2 可以改進的內容

1. 生產中的工單可以登錄停工，選擇停工原因，系統記下停工的開始時間
2. 恢復生產時登錄恢復，系統記下結束時間，算得出這次停了多久
3. 未完工清單上看得出哪些工單停著、停了多久、為什麼停
4. 依原因與工作中心統計停工次數與時間

### 3.3 改完之後要解決的問題

| 改完要做到 | 對應的缺點 |
|---|---|
| 生管人員不必到現場，就知道哪一張單停了 | 工單停下來，系統上看不出來 |
| 每一次停工的起訖時間查得到，交期延誤時說得出時間耗在哪裡 | 不知道停了多久 |
| 查得出哪一種原因、哪一個工作中心最常停工 | 停工原因沒有地方記 |
| 停工中的單在清單上一眼分得出來 | 停工的單混在生產中的單裡 |

### 3.4 待小組決議的問題（必須將答案放在報告裡）

- 誰登錄停工與恢復：只有組長，還是生管人員也可以？組長忘了按恢復怎麼辦
- 停工原因怎麼分類、由誰維護？選不到合適的原因時怎麼辦？如果 CR-02 也一起做，停工原因與不良原因要不要用同一種維護方式
- 一張工單可以停好幾次嗎？每一次怎麼呈現
- 停工中的工單能不能改派到別的工作中心、能不能取消、能不能直接回報完工
- 已派工、還沒開工的工單延後開工，算不算停工
- 停工超過多久要提醒生管人員，還是清單上看得到就好
- 上線以來的工單沒有停工紀錄，改版後怎麼呈現

## 四、CR-02 分批報工與工時

### 4.1 原有系統的缺點

| 缺點 | 現場發生什麼事 |
|---|---|
| 生產中看不到做了多少 | 一張工單常要做好幾天，中間只有「生產中」三個字。生管人員想知道趕不趕得上交期，只能到現場問 |
| 跨班生產只能由一個人回報一次 | 夜班組長開工、早班組長完工，兩班各做了多少只能寫在完工備註裡 |
| 不記誰做、做了幾小時 | 不知道一張工單用了多少工時，下次排預定生產日只能憑經驗 |
| 不良數只有一個總數 | 不良原因寫在備註裡，想知道哪一種不良最多，只能一張一張讀 |

用任一帳號登入，打開 WO-261027-01：1200 件曲柄在 10-29 開工，交期是 11-06，只剩 1 天，系統上看不出已經做了幾件。再打開 WO-261020-01：夜班組長羅士傑在 10-22 晚上開工，早班組長曾國峰在 10-27 回報完工，完工備註寫著「早班 300、夜班 288；不良 12 件為夾痕」，兩班各做多少、為什麼不良，都只留在這段文字裡。WO-261005-01 的完工備註也是同樣的寫法。

### 4.2 可以改進的內容

1. 生產中可以分好幾次回報，每次記下良品數、不良數與回報時間
2. 每次回報記下是哪一班或哪些作業員做的、做了幾小時
3. 生管人員隨時看得到每張生產中工單的累計數量
4. 不良數依原因分類回報

### 4.3 改完之後要解決的問題

| 改完要做到 | 對應的缺點 |
|---|---|
| 生管人員不必到現場就知道一張工單做到哪裡 | 生產中看不到做了多少 |
| 每一班做了多少，在系統上分得開 | 跨班生產只能由一個人回報一次 |
| 一張工單用了多少工時查得到，可以拿來排下一次的預定生產日 | 不記誰做、做了幾小時 |
| 查得出哪一種不良最常發生 | 不良數只有一個總數 |

### 4.4 待小組決議的問題（必須將答案放在報告裡）

- 多久回報一次：每班一次、每做完一箱，還是組長自己決定？規定太細，組長會不會乾脆最後一次補
- 誰來回報：還是只有組長，還是作業員也要有帳號？作業員旁邊沒有電腦時怎麼辦
- 工時記到多細：每位作業員各自的時數，還是一班的總人時？機台的運轉時間要不要記
- 累計數量到達工單數量時自動完工，還是組長要另外按完工
- 累計數量超過或不到工單數量時，系統怎麼處理
- 回報填錯了能不能修改或刪除？修改要留下紀錄嗎
- 上線以來已完工的工單只有一筆總數，改版後怎麼呈現

## 五、修改時的限制

| 限制 | 說明 |
|---|---|
| 技術不變 | 仍是 HTML + CSS + JavaScript，資料存在 SQLite 資料庫檔 |
| 可以新增 | 可以在既有資料表加欄位，也可以新增資料表 |
| 原有規則照舊 | 例如工單不得刪除、工單號的編碼方式不變、生管人員不能代替組長回報 |
| 範圍只到這兩項 | 多製程途程（一張工單依序經過好幾道製程）、自動排程與產能負荷計算、物料領用與庫存、不良品的重工與報廢、客戶訂單管理，這次不做 |
| 不必改程式 | 報告寫到需求、流程、資料與畫面為止。依你的修改建議實際改程式，是[額外投入加分](../../00-Course-Introduction/Bonus-Rules.md)的項目 |

## 六、你要交出什麼

期末報告分兩大部分：

| 部分 | 內容 |
|---|---|
| 第一部分：既有系統分析簡要報告 | 分析系統現在的樣子：背景與角色、現況流程、現況功能與需求、現況資料 |
| 第二部分：修改建議書 | 把這份提案書的兩項需求，寫成正式的變更需求，再寫出修改前後的差異、會影響到哪裡、修改後的規格、資料與畫面怎麼改、怎麼驗收 |

這份提案書只說「要解決什麼問題」，不說「要怎麼改」。〈3.4〉與〈4.4〉的問題沒有標準答案，你的選擇與理由要寫進報告。每一項寫什麼、寫到多細，照[系統修改範例報告](../../04-Final-Project-Example-Reports/Final-Phase-Sample-Report.md)的結構。

## 七、名詞解釋

| 名詞 | 意思 |
|---|---|
| 工單 | 生產工單，生管要求現場做一批產品的指令，記載產品、數量與交期 |
| 工作中心 | 一群做同一類加工的機台與人員，例如 CNC 車削組、組裝線 |
| 製程 | 把材料加工成產品的其中一個步驟，例如車削、銑削、組裝 |
| 途程 | 一個產品依序要經過哪些製程、每一道在哪個工作中心做 |
| 派工 | 替工單選定由哪個工作中心、在哪一天生產 |
| 報工 | 現場回報生產的數量與狀況。**做完才報一次與分批報，生管看到的資訊不同** |
| 良品數、不良數、良率 | 良品數是合格的件數，不良數是不合格的件數；良率是良品數占兩者合計的比例 |
| 工時 | 做這張工單花掉的人力時間，常用「人時」計算，例如 3 個人做 2 小時是 6 人時 |
| 停工 | 生產中途因為待料、機台故障、等品檢等原因停下來，之後再恢復生產。**停工要記到多細，是設計出來的** |
| 待料 | 生產需要的材料還沒到，只能等 |
