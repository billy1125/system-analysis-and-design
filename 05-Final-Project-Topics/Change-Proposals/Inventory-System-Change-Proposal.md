# 倉庫盤點管理系統：修改需求提案書

> 老師提供一套已經在使用的[倉庫盤點管理系統](../SAD-Inventory/README.md)，現在工廠提出一項新需求。請先操作系統、讀懂它現在怎麼運作，再想清楚系統要怎麼改，寫成期末報告。

---

## 一、系統現況

某中型辦公家具製造廠的資材倉庫，在 2026-09-01 用這套系統取代 Excel 帳與手寫盤點清單：倉管人員登錄入庫與出庫，系統維護每個料號的帳面數量；盤點時主管建立盤點單、指派盤點人員，盤點人員輸入實盤數量，主管結案時系統把帳面改成實盤數量。

倉庫帳看起來只是記下每個料號有幾個，其實是採購、生產與財務共用的數字，帳錯了，後面每個決定都會跟著錯。沒有做好倉庫帳與盤點，遇到下面兩種情況就很難處理：

- **缺料或重複採購**：帳面多於實物，生產領料時才發現缺料；帳面少於實物，會重複採購、積壓資金。
- **帳實不符**：盤點發現差異，要能回頭查是哪一筆入庫或出庫出了問題；財務結算也要用盤點後的數字。

Excel 帳與手寫盤點清單容易改錯、對不起來，也查不到誰改過，這是倉庫改用系統的原因。

| 項目 | 現況 |
|---|---|
| 使用者 | 資材倉庫的主管與倉管人員。年度盤點時來支援的其他部門同仁不使用這套系統 |
| 使用地點 | 系統裝在倉庫辦公室的一台電腦，倉庫內的電腦以瀏覽器連線 |
| 規模 | 7 個畫面、5 張資料表、2 種角色 |
| 主要功能 | 盤點單清單、建立盤點單（全盤或抽盤）、輸入實盤數量、盤點結案並調整帳面、料號清單與維護、登錄入庫與出庫、異動紀錄查詢、帳號維護 |

## 二、修改需求

| 編號 | 需求 | 提出者 | 一句話說明要解決的問題 |
|---|---|---|---|
| CR-01 | 覆盤與差異核准 | 倉庫課長 | 重新輸入就蓋掉前一次的數字，盤差多大都整張一起調帳，主管分不出哪些數字可信 |

CR 是 Change Request（變更申請）的縮寫，實務上每一項系統修改都會編一個號碼，方便後續追蹤。

這一項是**新的需求**，不是修正錯誤。現行系統運作正常，只是當初沒有納入這個範圍。

## 三、CR-01 覆盤與差異核准

![CR-01 覆盤與差異核准](images/inventory-recount-approval-comic.png)

*本圖由 ChatGPT 生成，已由作者審核內容正確性*

### 3.1 原有系統的缺點

| 缺點 | 現場發生什麼事 |
|---|---|
| 重新輸入會蓋掉前一次的數量 | 覺得數錯就重數，第一次的數字從系統上消失，看不出這一項被數過幾次 |
| 盤差多大都一樣處理 | 差 1 盒螺絲和差 50 個紙箱，結案時都直接調進帳面 |
| 有盤差也不必寫原因 | 差異說明不是必填，事後查不出帳面為什麼被調整 |
| 只能整張結案 | 有一項數字還有疑問，整張單就結不了案；一旦結案，所有盤差一起調進帳面 |

用任一帳號登入，打開 IC-2611-01：PL-2002 美耐板桌面帳面 38 片、實盤 40 片，差異說明寫「早上數 38，覆盤後改為 40」。第一次數的跟帳面一樣，重數之後反而多出 2 片。系統只留下 40 這個數字，38 只剩在說明裡；說明不是必填，沒寫的話就看不出這一項重數過。再打開 IC-2610-01：PL-2001 美耐板桌面盤虧 2 片，差異說明是空白，帳面照樣被調整。IC-2609-01 的 HW-3010 椅腳滑輪盤虧 6 個，說明寫「疑似組裝線領用未登記」，結案時就直接從帳面扣掉，系統上看不出有沒有人去查過。

### 3.2 可以改進的內容

1. 每一次輸入的實盤數量都保留下來，看得出一項被數過幾次、每次是誰數的
2. 盤差超過一定範圍時，要覆盤或寫明原因
3. 盤差調進帳面前要有人核准，有疑問的項目可以退回重數
4. 核准的人、時間與理由留在系統裡

### 3.3 改完之後要解決的問題

| 改完要做到 | 對應的缺點 |
|---|---|
| 一項數過幾次、每次數到多少，事後查得到 | 重新輸入會蓋掉前一次的數量 |
| 盤差大的項目一定經過覆盤或說明，才能調進帳面 | 盤差多大都一樣處理 |
| 每一筆盤點調整都查得到原因 | 有盤差也不必寫原因 |
| 有疑問的項目不會連帶卡住，也不會跟著其他項目一起被調進帳面 | 只能整張結案 |

### 3.4 待小組決議的問題（必須將答案放在報告裡）

- 差異容許範圍怎麼定：用數量、百分比，還是金額？每個料號都一樣嗎？系統現在沒有單價
- 覆盤由原來的盤點人員數，還是換一個人？一張盤點單現在只能指派一位盤點人員
- 覆盤後以哪一次為準：最後一次、兩次一致的那一次，還是由主管決定
- 誰有權核准？主管自己是盤點人員時，能不能核准自己數的
- 退回重數時怎麼表示？每一項要不要有自己的狀態
- 已核准的項目能不能先調帳、其他項目留著？這樣盤點單算不算結案
- 盤點人員輸入時看得到帳面數量，會不會傾向數到跟帳面一樣？要不要讓盤點人員看不到帳面
- 上線以來已結案的盤點單每一項只有一次數量，改版後怎麼呈現

## 四、修改時的限制

| 限制 | 說明 |
|---|---|
| 技術不變 | 仍是 HTML + CSS + JavaScript，資料存在 SQLite 資料庫檔 |
| 可以新增 | 可以在既有資料表加欄位，也可以新增資料表 |
| 原有規則照舊 | 例如異動紀錄與盤點單不得修改與刪除、帳面數量只能透過異動改變、盤點單號的編碼方式不變 |
| 範圍只到這一項 | 帳面快照與盤點期間的入庫出庫處理、條碼與手持裝置、採購與領料與出貨的單據、庫存金額與成本計算、多個倉庫，這次不做 |
| 不必改程式 | 報告寫到需求、流程、資料與畫面為止。依你的修改建議實際改程式，是[額外投入加分](../../00-Course-Introduction/Bonus-Rules.md)的項目 |

## 五、你要交出什麼

期末報告分兩大部分：

| 部分 | 內容 |
|---|---|
| 第一部分：既有系統分析簡要報告 | 分析系統現在的樣子：背景與角色、現況流程、現況功能與需求、現況資料 |
| 第二部分：修改建議書 | 把這份提案書的修改需求，寫成正式的變更需求，再寫出修改前後的差異、會影響到哪裡、修改後的規格、資料與畫面怎麼改、怎麼驗收 |

這份提案書只說「要解決什麼問題」，不說「要怎麼改」。〈3.4〉的問題沒有標準答案，你的選擇與理由要寫進報告。每一項寫什麼、寫到多細，照[期末範例報告](../../04-Final-Project-Example-Reports/Final-Phase-Sample-Report.md)的結構。

## 六、名詞解釋

| 名詞 | 意思 |
|---|---|
| 帳面數量 | 系統記載的庫存數量，入庫加、出庫減。**「現在的帳面數量」與「某個時間點的帳面數量」不是同一個值** |
| 實盤數量 | 盤點人員實際數出來的數量 |
| 盤差、盤盈、盤虧 | 盤差是實盤數量減帳面數量。正的叫盤盈（實際比帳上多），負的叫盤虧（實際比帳上少） |
| 全盤與抽盤 | 全盤是所有料號都盤；抽盤是只挑一部分料號盤 |
| 盤點調整 | 結案時依盤差修改帳面數量，系統留下一筆異動紀錄 |
| 覆盤 | 對有疑問的項目再數一次，常由另一個人來數 |
| 差異容許範圍 | 盤差在多少以內可以直接調整，超過就要覆盤或經過核准 |
