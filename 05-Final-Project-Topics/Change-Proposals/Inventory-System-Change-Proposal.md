# 倉庫盤點管理系統：修改需求提案書

> 老師提供一套已經在使用的[倉庫盤點管理系統](../SAD-Inventory/README.md)，現在工廠提出兩項新需求。請先操作系統、讀懂它現在怎麼運作，再想清楚系統要怎麼改，寫成期末報告。

---

## 一、系統現況

某中型辦公家具製造廠的資材倉庫，在 2026-09-01 用這套系統取代 Excel 帳與手寫盤點清單：倉管人員登錄入庫與出庫，系統維護每個料號的帳面數量；盤點時主管建立盤點單、指派盤點人員，盤點人員輸入實盤數量，主管結案時系統把帳面改成實盤數量。

| 項目 | 現況 |
|---|---|
| 使用者 | 資材倉庫的主管與倉管人員。年度盤點時來支援的其他部門同仁不使用這套系統 |
| 使用地點 | 系統裝在倉庫辦公室的一台電腦，倉庫內的電腦以瀏覽器連線 |
| 規模 | 7 個畫面、5 張資料表、2 種角色 |
| 主要功能 | 盤點單清單、建立盤點單（全盤或抽盤）、輸入實盤數量、盤點結案並調整帳面、料號清單與維護、登錄入庫與出庫、異動紀錄查詢、帳號維護 |

## 二、兩項修改需求

| 編號 | 需求 | 提出者 | 一句話說明要解決的問題 |
|---|---|---|---|
| CR-01 | 帳面快照與盤點期間異動 | 會計課長 | 盤點後有人領料，結案時系統把盤差算錯，錯的數字被調進帳面 |
| CR-02 | 覆盤與差異核准 | 倉庫課長 | 重新輸入就蓋掉前一次的數字，盤差多大都整張一起調帳，主管分不出哪些數字可信 |

CR 是 Change Request（變更申請）的縮寫，實務上每一項系統修改都會編一個號碼，方便後續追蹤。

這兩項都是**新的需求**，不是修正錯誤。現行系統運作正常，只是當初沒有納入這些範圍。

---

## 三、CR-01 帳面快照與盤點期間異動

### 3.1 原有系統的缺點

| 缺點 | 現場發生什麼事 |
|---|---|
| 盤點項目不記當時的帳面數量 | 盤差一律用料號「現在」的帳面計算，什麼時候打開明細，看到的盤差就可能不同 |
| 盤點期間照常可以入庫出庫 | 數完之後才領走的料，結案時被算成盤盈，帳面被調高 |
| 盤點期間的異動沒有另外列出 | 主管結案前看不出哪些料號在數完之後動過 |
| 輸入時與結案時的盤差可能不同 | 盤點人員依當時的盤差寫了說明，結案時盤差變了，說明就對不上數字 |

用任一帳號登入，打開 IC-2610-01：TB-1001 方形鋼管實盤 136 支、盤差 +16，差異說明卻寫「切料損耗未扣帳」。施博凱在 10-30 10:20 數的時候帳面是 140 支，盤差其實是 −4。到「庫存異動」查 TB-1001，會看到當天 14:00 有人領走 20 支，帳面變成 120 支；10-31 結案時系統用 120 支計算，把帳面調成 136 支，倉庫裡實際只剩 116 支。再打開還在盤點中的 IC-2611-01：PK-4001 五層紙箱實盤 300 個，11-04 盤點時盤差是 0；今天早上出庫 50 個之後，盤差變成 +50。如果現在結案，帳面會被調回 300 個。

### 3.2 可以改進的內容

1. 盤差以盤點當時的帳面數量計算，不隨之後的異動改變
2. 盤點期間的入庫與出庫有一致的處理方式
3. 主管結案前看得到每個料號在盤點之後有哪些異動
4. 結案調整的數量，從盤點紀錄與異動紀錄推得回來

### 3.3 改完之後要解決的問題

| 改完要做到 | 對應的缺點 |
|---|---|
| 同一張盤點單的盤差，不管什麼時候打開都一樣 | 盤點項目不記當時的帳面數量 |
| 數完之後的領料不會被算成盤盈 | 盤點期間照常可以入庫出庫 |
| 結案前就知道哪些料號在盤點期間動過 | 盤點期間的異動沒有另外列出 |
| 差異說明對應的就是調進帳面的那個盤差 | 輸入時與結案時的盤差可能不同 |

### 3.4 待小組決議的問題（必須將答案放在報告裡）

- 帳面數量在什麼時候記下來：建立盤點單時、開始數這一項時，還是輸入實盤數量時？時間點不同，「盤點期間」的範圍就不同
- 盤點期間要不要禁止這些料號入庫出庫？產線急著領料時怎麼辦
- 不禁止的話，盤點期間的異動怎麼算進結案的調整
- 異動時間是登錄的當下。現場先把料領走、晚一點才登錄時，系統怎麼知道這筆異動發生在盤點之前還是之後
- 記下來的帳面數量放在盤點項目上，還是另開一張資料表
- IC-2610-01 已經把 TB-1001 多調了 20 支，這筆錯誤要怎麼更正？現在異動紀錄不能修改也不能刪除
- 已結案的盤點單可以從盤點調整的異動推回當時的帳面，盤點中的 IC-2611-01 推不回來。改版時這張單怎麼處理

## 四、CR-02 覆盤與差異核准

### 4.1 原有系統的缺點

| 缺點 | 現場發生什麼事 |
|---|---|
| 重新輸入會蓋掉前一次的數量 | 覺得數錯就重數，第一次的數字從系統上消失，看不出這一項被數過幾次 |
| 盤差多大都一樣處理 | 差 1 盒螺絲和差 50 個紙箱，結案時都直接調進帳面 |
| 有盤差也不必寫原因 | 差異說明不是必填，事後查不出帳面為什麼被調整 |
| 只能整張結案 | 有一項數字還有疑問，整張單就結不了案；一旦結案，所有盤差一起調進帳面 |

用任一帳號登入，打開 IC-2611-01：PL-2002 美耐板桌面帳面 38 片、實盤 40 片，差異說明寫「早上數 38，覆盤後改為 40」。第一次數的跟帳面一樣，重數之後反而多出 2 片。系統只留下 40 這個數字，38 只剩在說明裡；說明不是必填，沒寫的話就看不出這一項重數過。再打開 IC-2610-01：PL-2001 美耐板桌面盤虧 2 片，差異說明是空白，帳面照樣被調整。IC-2609-01 的 HW-3010 椅腳滑輪盤虧 6 個，說明寫「疑似組裝線領用未登記」，結案時就直接從帳面扣掉，系統上看不出有沒有人去查過。

### 4.2 可以改進的內容

1. 每一次輸入的實盤數量都保留下來，看得出一項被數過幾次、每次是誰數的
2. 盤差超過一定範圍時，要覆盤或寫明原因
3. 盤差調進帳面前要有人核准，有疑問的項目可以退回重數
4. 核准的人、時間與理由留在系統裡

### 4.3 改完之後要解決的問題

| 改完要做到 | 對應的缺點 |
|---|---|
| 一項數過幾次、每次數到多少，事後查得到 | 重新輸入會蓋掉前一次的數量 |
| 盤差大的項目一定經過覆盤或說明，才能調進帳面 | 盤差多大都一樣處理 |
| 每一筆盤點調整都查得到原因 | 有盤差也不必寫原因 |
| 有疑問的項目不會連帶卡住，也不會跟著其他項目一起被調進帳面 | 只能整張結案 |

### 4.4 待小組決議的問題（必須將答案放在報告裡）

- 差異容許範圍怎麼定：用數量、百分比，還是金額？每個料號都一樣嗎？系統現在沒有單價
- 覆盤由原來的盤點人員數，還是換一個人？一張盤點單現在只能指派一位盤點人員
- 覆盤後以哪一次為準：最後一次、兩次一致的那一次，還是由主管決定
- 誰有權核准？主管自己是盤點人員時，能不能核准自己數的
- 退回重數時怎麼表示？每一項要不要有自己的狀態
- 已核准的項目能不能先調帳、其他項目留著？這樣盤點單算不算結案
- 盤點人員輸入時看得到帳面數量，會不會傾向數到跟帳面一樣？要不要讓盤點人員看不到帳面
- 如果 CR-01 也一起做，覆盤時的盤差要用哪一個時間點的帳面
- 上線以來已結案的盤點單每一項只有一次數量，改版後怎麼呈現

## 五、修改時的限制

| 限制 | 說明 |
|---|---|
| 技術不變 | 仍是 HTML + CSS + JavaScript，資料存在 SQLite 資料庫檔 |
| 可以新增 | 可以在既有資料表加欄位，也可以新增資料表 |
| 原有規則照舊 | 例如異動紀錄與盤點單不得修改與刪除、帳面數量只能透過異動改變、盤點單號的編碼方式不變 |
| 範圍只到這兩項 | 條碼與手持裝置、採購與領料與出貨的單據、庫存金額與成本計算、多個倉庫，這次不做 |
| 不必改程式 | 報告寫到需求、流程、資料與畫面為止。依你的修改建議實際改程式，是[額外投入加分](../../00-Course-Introduction/Bonus-Rules.md)的項目 |

## 六、你要交出什麼

期末報告分兩大部分：

| 部分 | 內容 |
|---|---|
| 第一部分：既有系統分析簡要報告 | 分析系統現在的樣子：背景與角色、現況流程、現況功能與需求、現況資料 |
| 第二部分：修改建議書 | 把這份提案書的兩項需求，寫成正式的變更需求，再寫出修改前後的差異、會影響到哪裡、修改後的規格、資料與畫面怎麼改、怎麼驗收 |

這份提案書只說「要解決什麼問題」，不說「要怎麼改」。〈3.4〉與〈4.4〉的問題沒有標準答案，你的選擇與理由要寫進報告。每一項寫什麼、寫到多細，照[系統修改範例報告](../../04-Final-Project-Example-Reports/Final-Phase-Sample-Report.md)的結構。

## 七、名詞解釋

| 名詞 | 意思 |
|---|---|
| 帳面數量 | 系統記載的庫存數量，入庫加、出庫減。**「現在的帳面數量」與「某個時間點的帳面數量」不是同一個值** |
| 實盤數量 | 盤點人員實際數出來的數量 |
| 盤差、盤盈、盤虧 | 盤差是實盤數量減帳面數量。正的叫盤盈（實際比帳上多），負的叫盤虧（實際比帳上少） |
| 全盤與抽盤 | 全盤是所有料號都盤；抽盤是只挑一部分料號盤 |
| 盤點調整 | 結案時依盤差修改帳面數量，系統留下一筆異動紀錄 |
| 快照 | 把某個時間點的數值另外存下來。之後原本的數值改變，存下來的不會跟著變 |
| 凍結 | 盤點期間暫停這些料號的入庫與出庫 |
| 覆盤 | 對有疑問的項目再數一次，常由另一個人來數 |
| 差異容許範圍 | 盤差在多少以內可以直接調整，超過就要覆盤或經過核准 |
