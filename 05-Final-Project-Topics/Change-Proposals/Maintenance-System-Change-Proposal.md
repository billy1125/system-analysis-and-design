# 設備保養紀錄管理系統：修改需求提案書

> 老師提供一套已經在使用的[設備保養紀錄管理系統](../SAD-Maintenance/README.md)，現在工廠提出兩項新需求。請先操作系統、讀懂它現在怎麼運作，再想清楚系統要怎麼改，寫成期末報告。

---

## 一、系統現況

某中型金屬加工廠的設備課，在 2026-08-01 用這套系統取代設備旁的紙本保養表：主管替每台設備設定保養計畫，保養人員做完保養後在系統上逐項登錄結果，系統依上次保養日算出下次應保養日。

| 項目 | 現況 |
|---|---|
| 使用者 | 設備課的主管與保養人員。操作員不使用這套系統 |
| 使用地點 | 系統裝在設備課的一台電腦，廠內電腦以瀏覽器連線 |
| 規模 | 8 個畫面、5 張資料表、2 種角色 |
| 主要功能 | 待保養清單、逐項登錄保養結果、保養紀錄查詢、設備保養履歷、設備與保養計畫維護、帳號維護 |

## 二、兩項修改需求

| 編號 | 需求 | 提出者 | 一句話說明要解決的問題 |
|---|---|---|---|
| CR-01 | 年度保養計畫與逾期紀錄 | 品保部 | 排不出全年的保養計畫，逾期過的那一次做完就看不出來 |
| CR-02 | 保養異常追蹤 | 設備課長 | 保養時發現的異常只寫在說明裡，不知道後來有沒有處理 |

CR 是 Change Request（變更申請）的縮寫，實務上每一項系統修改都會編一個號碼，方便後續追蹤。

這兩項都是**新的需求**，不是修正錯誤。現行系統運作正常，只是當初沒有納入這些範圍。

---

## 三、CR-01 年度保養計畫與逾期紀錄

### 3.1 原有系統的缺點

| 缺點 | 現場發生什麼事 |
|---|---|
| 下次應保養日一律從上一次實際保養日往後推 | 每次晚幾天，日期就一路往後漂。客戶稽核要看「全年的保養計畫表」，系統排不出來，品保部只能另外用 Excel 排 |
| 逾期沒做的那一次不留紀錄 | 系統只看得到「現在逾期幾天」。保養做完之後，逾期的痕跡就消失了 |
| 沒有延期的申請與核准 | 產線趕貨不能停機時，保養人員自己往後延，主管事後才知道，理由頂多寫在備註裡 |
| 統計不出保養達成率 | 稽核問「這一季應做幾次、按時做了幾次」，沒有人答得出來 |

用主管帳號 `E5001` 登入，打開「設備」，點 EQ-001 看保養履歷：月保養原訂 2026-09-04 要做，因為趕貨拖到 09-24 才做，系統直接從 09-24 往後算下一次。這 20 天的逾期，只留在保養人員自己寫的備註裡。再看待保養清單上的 EQ-012：月保養原訂 2026-10-16 要做，到現在還沒做。只要有人登錄一次保養，它就會從逾期清單上消失，系統不會記得它曾經逾期。

### 3.2 可以改進的內容

1. 保養計畫排得出全年的應保養日期，可以印出或在畫面上看年度保養計畫表
2. 每一次應該保養都看得到結果：按時做、逾期才做、延期、還沒做
3. 產線不能停機時，保養人員可以申請延期，由主管核准，延期理由與核准人留在系統
4. 依期間與設備統計保養達成率

### 3.3 改完之後要解決的問題

| 改完要做到 | 對應的缺點 |
|---|---|
| 品保部不必另外用 Excel 排計畫，客戶稽核直接看系統 | 下次應保養日一路往後漂 |
| 逾期過的那一次事後查得到，逾期幾天也查得到 | 逾期沒做的那一次不留紀錄 |
| 延期事前就有人核准，事後查得到理由 | 沒有延期的申請與核准 |
| 稽核問達成率時，系統算得出來 | 統計不出保養達成率 |

### 3.4 待小組決議的問題（必須將答案放在報告裡）

- 下次應保養日要從原訂日往後推，還是從實際保養日往後推？如果兩種都要支援，要由誰決定，記在哪裡
- 月保養現在是每 30 天一次，不是每月固定一天。年度計畫表上的月保養要排在每月固定一天，還是每 30 天一次？每 30 天一次的話，一年會排出 12 或 13 次
- 「應該保養的那一次」要不要先存成一筆資料？如果要，什麼時候產生、要產生多遠以後的日期
- 主管改了保養週期，已經排好的未來日期要不要重排
- 延期可以延到哪一天、可以延幾次？延期之後，下一次從延後的日期還是原訂日起算
- 「按時」怎麼定義：一定要在原訂日當天，還是前後幾天內都算？提前做算不算按時
- 達成率的分母是什麼？停用的設備、延期核准過的那一次，要不要算進去
- 上線以來的舊紀錄沒有「原訂日」，改版後要怎麼補

## 四、CR-02 保養異常追蹤

### 4.1 原有系統的缺點

| 缺點 | 現場發生什麼事 |
|---|---|
| 異常只是項目結果的說明文字，沒有處理狀態 | 「已請採購叫料」之後，零件到了沒、換了沒，系統看不出來。現場處理完的異常和還沒處理的異常，在系統裡長得一樣 |
| 異常沒有負責人，也沒有預定完成日 | 發現的人寫完說明就結束了，沒有人被指定要處理 |
| 下一次保養的人看不到上一次的異常 | 登錄保養時畫面只帶出保養項目，不知道這台設備上次有什麼問題 |
| 主管看不到目前還有幾件沒處理完 | 只能用「有異常」篩選全部保養紀錄，再一筆一筆看說明 |

用任一帳號登入，打開「保養紀錄」，紀錄結果選「有異常」：會列出兩筆。EQ-032 的風扇皮帶鬆動，當場調整好了；EQ-002 的離合器來令片磨損約 7 成，寫著「已請採購叫料」，後來有沒有換，系統裡查不到。兩筆在清單上看起來沒有差別。

### 4.2 可以改進的內容

1. 保養時發現的異常可以單獨列管，記錄處理狀態、負責人與預定完成日
2. 列出所有還沒處理完的異常，可以依設備與負責人篩選
3. 處理完要登錄處理方式與完成日期
4. 登錄保養時，畫面上看得到這台設備還沒處理完的異常

### 4.3 改完之後要解決的問題

| 改完要做到 | 對應的缺點 |
|---|---|
| 每一件異常都知道處理到哪裡、什麼時候處理完 | 異常沒有處理狀態 |
| 每一件異常都有人負責、有期限 | 異常沒有負責人與預定完成日 |
| 保養人員到現場前就知道這台設備有什麼待處理的問題 | 下一次保養的人看不到上一次的異常 |
| 主管一個畫面就看得到所有未處理的異常 | 主管看不到還有幾件沒處理完 |

### 4.4 待小組決議的問題（必須將答案放在報告裡）

- 異常要另外存成一筆資料，還是在項目結果上加幾個欄位？同一件異常可能要處理好幾次，例如先叫料、零件到了再更換
- 保養當下已經處理好的異常，例如 EQ-032 的皮帶，也要列管嗎？還是登錄時就能直接結案
- 處理異常需要停機修理時，跟「故障維修」的界線在哪裡？這一題不做故障維修
- 「未執行」的項目要不要跟異常一起追？下一次保養做了這一項，算不算補做完
- 異常的負責人可以指派給誰？叫料的採購人員、外包的維修廠商，都沒有這套系統的帳號
- 誰可以把異常結案：處理的人自己，還是要主管確認
- 異常還沒處理完，下一次保養就到期了，要照做還是申請延期？例如 EQ-002 的離合器在等料，下一次月保養 2026-11-07 到期。如果 CR-01 也一起做，延期理由能不能指向這件異常
- 已經登錄過的異常與未執行項目，改版後要不要轉成待追蹤的事項

## 五、修改時的限制

| 限制 | 說明 |
|---|---|
| 技術不變 | 仍是 HTML + CSS + JavaScript，資料存在 SQLite 資料庫檔 |
| 可以新增 | 可以在既有資料表加欄位，也可以新增資料表 |
| 原有規則照舊 | 例如保養紀錄不得刪除、登錄時保存當下的保養項目文字 |
| 範圍只到這兩項 | 操作員的日常點檢、故障維修、依感測器資料決定保養時機，這次不做 |
| 不必改程式 | 報告寫到需求、流程、資料與畫面為止。依你的修改建議實際改程式，是[額外投入加分](../../00-Course-Introduction/Bonus-Rules.md)的項目 |

## 六、你要交出什麼

期末報告分兩大部分：

| 部分 | 內容 |
|---|---|
| 第一部分：既有系統分析簡要報告 | 分析系統現在的樣子：背景與角色、現況流程、現況功能與需求、現況資料 |
| 第二部分：修改建議書 | 把這份提案書的兩項需求，寫成正式的變更需求，再寫出修改前後的差異、會影響到哪裡、修改後的規格、資料與畫面怎麼改、怎麼驗收 |

這份提案書只說「要解決什麼問題」，不說「要怎麼改」。〈3.4〉與〈4.4〉的問題沒有標準答案，你的選擇與理由要寫進報告。每一項寫什麼、寫到多細，照[系統修改範例報告](../../04-Final-Project-Example-Reports/Final-Phase-Sample-Report.md)的結構。
