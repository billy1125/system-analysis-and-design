# 倉庫盤點管理系統

> **領域**：物料與倉儲｜**難度**：標準｜**這一題要想清楚的問題**：盤點的時候倉庫還在出貨，帳面數量要凍結成快照，還是每次即時去讀？
>
> 五題共通的名詞見本資料夾的[期末設計題目說明](README.md)〈五〉。

---

## 一、先看懂這件事在說什麼

### 1.1 一個你已經懂的類比

你的悠遊卡 App 顯示餘額 320 元，但你去便利商店刷，機器說只有 180 元。**帳上的數字跟實際的數字不一樣了。**

要知道差在哪，只能拿一份帳上的紀錄，跟實際的狀況一項一項比對。比完之後，你得決定：是相信帳，還是相信實際？

**倉庫盤點就是這件事，只是要比對的不是一個數字，而是幾百個料號。**

### 1.2 現場實際長什麼樣

工廠的倉庫裡有幾百到幾千種料號，系統或帳冊上每一種都有一個數量。但實際去數，數字常常對不上——領料忘了登記、退料放回去沒入帳、報廢了沒扣掉、數錯了。

所以每隔一段時間要盤點：把倉庫實際有多少東西數清楚，跟帳上的數字比對，差多少、為什麼差、要不要調整帳面。

一間中小型工廠的實際狀況大致是這樣：

| 面向 | 現況 |
|---|---|
| 多久盤一次 | 全廠年度盤點一次；重要料號可能每月抽盤 |
| 怎麼盤 | 倉管印出一份料號清單，兩人一組拿著清單去數，數完寫在紙上 |
| 誰在盤 | 倉管人員，年度盤點時會抓其他部門的人來幫忙 |
| 比對 | 回辦公室把手寫的數字一筆一筆敲進 Excel，跟帳面數量相減 |
| 差異怎麼辦 | 差得多的幾項回去重數一次，其餘寫個理由，主管簽名後調整帳面 |

出問題通常是在盤點期間倉庫沒停：

> 「這一項帳上 500，我數出來 480。」
> 「你什麼時候數的？」
> 「兩點多。」
> 「那大概是三點有人領走 20 支，你的數字是對的。」

### 1.3 名詞解釋

| 名詞 | 意思 |
|---|---|
| 盤點 | 清點實際庫存數量，與帳面比對 |
| 盤點單 | 一次盤點作業的紀錄，包含要盤哪些料號、各盤出多少 |
| 帳面數量 | 系統或帳冊上記載的數量 |
| 實盤數量 | 實際數出來的數量 |
| 盤差 | 實盤數量減去帳面數量。**正的叫盤盈，負的叫盤虧** |
| 全盤與抽盤 | 全盤是所有料號都盤；抽盤是只挑一部分 |
| 循環盤點 | 不停工，分批輪流盤，一年下來每一項都盤過 |
| 覆盤（複盤） | 差異太大時再數一次確認 |
| 帳面調整 | 確認實盤正確後，把帳面數量改成實際數量 |
| 凍結（結凍） | 盤點期間暫停該料號的出入庫異動，避免邊數邊變 |

**「盤差」不是錯誤，是資訊。** 差異本身要記錄下來、要有原因、要有人核可調整。你的設計不能只做到「算出差多少」就停，因為現場真正在乎的是那之後的事。

## 二、為什麼需要一套系統

### 2.1 現在的做法有什麼問題

| 問題 | 具體情況 |
|---|---|
| 手抄再輸入，錯兩次 | 現場寫在紙上、回辦公室敲進 Excel，兩個環節都會抄錯 |
| 進度看不出來 | 五個人在盤，不知道盤到第幾項、誰還沒回報 |
| 差異原因沒留下 | Excel 上只有一欄數字，為什麼差沒有人記 |
| 覆盤沒有紀錄 | 第二次數的數字直接蓋掉第一次，看不出來重數過 |
| 誰核准的說不清 | 主管口頭說可以調，事後查不到是誰決定的 |
| 上一次盤點查不到 | 檔案存在某個人的電腦裡 |

### 2.2 系統要解決哪幾件事

1. 建立一張盤點單，指定這次要盤哪些料號、由誰負責。
2. 現場輸入實盤數量，系統自動算出盤差。
3. 差異超過一定範圍的要填原因，或安排覆盤。
4. 盤點進度隨時看得到：盤了幾項、還剩幾項。
5. 帳面調整要有人核准，且留下紀錄。
6. 歷次盤點紀錄都查得到。

## 三、誰會用這套系統

| 角色 | 現場的實際身分 | 在這套系統裡做什麼 | 多久用一次 | 最在意什麼 |
|---|---|---|---|---|
| 盤點人員 | 倉管人員，或被調來支援的其他部門同仁 | 領到自己負責的清單、輸入實盤數量、填差異說明 | 盤點期間密集使用 | **輸入要快。** 站在料架前面，手上拿著掃碼槍或平板 |
| 倉管主管 | 倉庫課長 | 建立盤點單、指派人員、看進度、審核差異、核准調整 | 每次盤點 | 進度與差異要一眼看得出來 |

**「盤點期間密集使用、平常完全不用」是這一題的特色。** 一年只用幾次的系統，介面必須讓一個久久用一次的人立刻上手，而不是靠訓練與熟練度。

## 四、要管哪些東西

以下用白話列出這套系統要記錄的資訊。**怎麼拆成資料表、每張表有哪些欄位，是你的工作，這裡不給。**

**關於每一種料**

- 料號、品名、規格
- 單位（支、個、公斤、箱）
- 存放的儲位
- 目前的帳面數量

**關於每一次盤點作業**

- 這次盤點的名稱與期間
- 是全盤還是抽盤
- 誰建立的、目前進行到哪個階段

**關於盤點單上的每一個料號**

- 是哪一種料
- 盤點時的帳面數量
- 實盤數量
- 誰盤的、什麼時候盤的
- 差異說明
- 有沒有覆盤、覆盤的數量是多少

**注意這三組資訊的關係。** 一次盤點作業包含幾百個料號，每一個料號各有自己的實盤數量與差異——這是主檔與明細的結構。**三層之間怎麼關聯、各層有哪些欄位，你要自己決定。**

## 五、一張盤點單的一生

```text
建立盤點單（決定盤哪些料號、指派人員）
  → 產生盤點明細，狀態為未盤
  → 現場輸入實盤數量（狀態：已盤）
  → 系統算出盤差
  → 差異在容許範圍內 ─────────→ 待審核
  → 差異超過容許範圍 → 安排覆盤 → 重新輸入 → 待審核
  → 主管審核通過 → 調整帳面 → 盤點完成（終點）
  → 主管退回 → 回到「安排覆盤」
```

**例外會發生在這幾個地方，設計時都要有答案：**

| 環節 | 例外情況 | 你要決定什麼 |
|---|---|---|
| 盤點中 | 有人在盤點期間領走了料 | 帳面數量要不要凍結？這是第六節的核心 |
| 盤點中 | 現場找到一項清單上沒有的料 | 可以臨時加進盤點單嗎？ |
| 輸入 | 同一個料號被兩個人各盤了一次，數字不同 | 以誰為準？兩筆都留還是覆蓋？ |
| 覆盤 | 覆盤數量跟第一次一樣 | 那到底是帳錯還是人錯？系統要怎麼呈現 |
| 結束 | 盤點結束時還有幾項沒盤到 | 可以結束嗎？沒盤到的怎麼記？ |

**「盤點期間有人領走了料」這一條是本題的核心**，它直接引出第六節的取捨。

## 六、這一題要想清楚的地方

### 6.1 問題在哪

盤點單上有一欄「帳面數量」，用來跟實盤數量比對算出盤差。

**問題是：帳面數量隨時在變。** 早上十點建立盤點單時是 500，下午兩點你去數，數出 480，但這中間有人領走了 20。這時候盤差是 −20 還是 0？

答案取決於「帳面數量」這個欄位講的是哪一個時間點的數字。

### 6.2 兩種做法，各自的代價

**做法 A：建立盤點單時，把帳面數量抄一份存進明細（快照）**

| | |
|---|---|
| 好處 | **比對的基準固定。** 盤差算出來就不會再變，事後查得出當時帳面是多少 |
| 代價 | 快照之後發生的出入庫不會反映進來，那 20 支的差異要另外解釋 |
| 配套 | 通常要搭配「盤點期間凍結該料號的異動」，或至少把盤點期間的異動單獨列出來 |

**做法 B：不存快照，比對的時候即時去讀目前的帳面數量**

| | |
|---|---|
| 好處 | 永遠是最新的數字，不用維護第二份資料 |
| 代價 | **盤差會自己變。** 早上看是 −20，下午再看變成 −35，因為中間又出貨了 |
| 額外問題 | 主管審核的時候看到的數字，跟盤點人員當時看到的不一樣，兩個人會吵起來 |

### 6.3 選了 A 之後還有一個問題

「盤點期間要不要凍結出入庫」是一個管理決定，不完全是系統決定：

| 選項 | 好處 | 代價 |
|---|---|---|
| 完全凍結（停工盤點） | 數字最乾淨 | 生產要停，中小型工廠通常只有年度盤點做得到 |
| 不凍結，但把盤點期間的異動列出來 | 生產照常 | 差異要人工判讀，「這 20 支是盤點後領的」要有人去核對 |
| 只凍結正在盤的那幾個料號 | 折衷 | 系統要知道哪些料號正在被盤，複雜度上升 |

### 6.4 這一題會逼你回答什麼

期末第 4 項〈資料設計〉要求你說明「這個畫面上的欄位最後存在哪裡」。

這一題的關鍵欄位是「帳面數量」——它到底是盤點明細上的一個欄位，還是每次去料號主檔讀出來的？兩種做法會生出完全不同的資料表結構。

能把這個選擇與它的配套規則寫清楚，代表你理解了「同一個數字在不同時間點會不一樣」這件事對資料設計的影響。這是本題最主要的學習點，也是訪談一定會問的地方。

**要選 A 還是 B，你自己決定，理由要寫進第 8 項的設計決策紀錄。**

## 七、容易走偏的方向

| 走偏的做法 | 為什麼不對 |
|---|---|
| 只做「輸入實盤數量、算出差異」就結束 | 盤點的價值在差異之後的處理：原因、覆盤、核准、調整。少了這一段就只是一台計算機 |
| 把盤點做成完整的進銷存系統 | 範圍會爆掉。本題假設帳面數量已經存在，你不必設計出入庫作業 |
| 做成自動預測盤差或異常偵測 | 演算法會吃掉整份報告 |
| 覆盤直接覆蓋原本的數字 | 覆盤過的紀錄要留著，否則看不出這一項被重數過 |
| 差異一律自動調整帳面 | 帳面調整必須有人核准，這是稽核要求，不是設計偏好 |
| 忽略「哪些還沒盤」 | 盤點進度是這套系統對主管最主要的價值 |

## 八、第一週建議做什麼

1. **去找一張真的盤點表。** Google「盤點表 範本」「庫存盤點單」找得到大量實例。把上面每一個欄位抄下來，逐一問：這一欄是誰填的？什麼時候填？
2. **找一位實習過倉儲或生管的學長姐問十分鐘**：你們怎麼盤、盤點期間倉庫停不停。
3. **自己模擬一次**：拿一份 10 個項目的清單，請同學在你「盤點」的過程中偷偷拿走一項，然後看你的設計怎麼呈現這個差異。
4. **決定第六節那個取捨**（帳面數量存快照或即時讀），把理由寫成三句話。這三句話會直接進第 8 項的設計決策紀錄。

第 4 步最重要。**這個決定做完，這一題有一半就想通了。**
