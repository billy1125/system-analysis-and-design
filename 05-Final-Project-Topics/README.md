# 期末題目

這個資料夾收錄期末小組報告（系統分析與修改建議）的題目。期末共五題，每一題是一套已經在工廠使用的管理系統，加上一份老師提供的修改需求提案書。各組做哪一題由當堂公開抽籤決定，方式見[SAD 課程介紹](../00-Course-Introduction/Course-Introduction.md)〈題目怎麼分配〉。

## 一、每一題給你什麼

期末不是從零設計一套新系統，而是先看懂一套既有系統，再依提案書提出修改建議。每一題有兩樣東西，加上兩份全班共用的文件：

| 文件 | 回答的問題 | 什麼時候看 |
|---|---|---|
| 既有系統（`SAD-<名稱>/`） | 系統現在怎麼運作：怎麼安裝啟動、有哪些帳號與畫面、資料存在哪裡 | 抽到題目後，先裝起來操作 |
| 修改需求提案書（`Change-Proposals/`） | 工廠要改什麼、為什麼要改、改完要解決什麼問題、有哪些要你想清楚 | 操作過系統之後 |
| [報告內容](../00-Course-Introduction/Report-Contents.md)〈二〉 | 兩大部分 16 項要交什麼（規定的事實來源） | 確認要交什麼 |
| [系統修改範例報告](../04-Final-Project-Example-Reports/Final-Phase-Sample-Report.md) | 交出去的成品長什麼樣 | 想知道整份的長相與詳細程度時 |

範例報告的示範對象是**工廠訪客進出登記系統**，那是上課帶著大家做的題目，**刻意不在下面五題之中**。它的既有系統在 [`SAD-Visitor/`](SAD-Visitor/README.md)，修改方向見[修改需求提案書](Change-Proposals/Visitor-System-Change-Proposal.md)，依提案書改完的版本在 [`SAD-Visitor-Revised/`](SAD-Visitor-Revised/README.md)（這是加分項目的示範，不是必做）。你可以照抄它的結構與寫法，但抄不到答案。

五題一覽見〈三〉，使用步驟見〈四〉，不建議做的方向見〈七〉。各題的名詞解釋放在該題提案書的最後一節。

## 二、這些文件不會給你什麼

**不給既有系統的分析結果，也不給修改後的資料表、畫面與測試案例。**

系統的畫面、程式與資料庫都在，但流程圖、功能需求清單、ERD 與資料字典要你自己從系統整理出來，那是第一部分的工作。修改後長什麼樣，是第二部分的工作。兩者都是分數所在。

提案書每一項修改需求的最後都有〈請你想清楚〉，會把要決定的問題攤開，但**不告訴你該選哪一個**。你們的選擇與理由，就是第二部分〈變更申請〉裡真正屬於你們的內容。照抄不來，也問不到標準答案。

## 三、五個題目一覽

| 題目 | 領域 | 既有系統 | 修改需求提案書 | 修改需求 |
|---|---|---|---|---|
| 品質異常回報管理系統 | 品質管理 | [SAD-Quality](SAD-Quality/README.md) | [修改需求提案書](Change-Proposals/Quality-System-Change-Proposal.md) | CR-01 對策確認與退回、CR-02 現場直接回報與照片 |
| 倉庫盤點管理系統 | 物料與倉儲 | [SAD-Inventory](SAD-Inventory/README.md) | [修改需求提案書](Change-Proposals/Inventory-System-Change-Proposal.md) | CR-01 帳面快照與盤點期間異動、CR-02 覆盤與差異核准 |
| 設備保養紀錄管理系統 | 設備維護 | [SAD-Maintenance](SAD-Maintenance/README.md) | [修改需求提案書](Change-Proposals/Maintenance-System-Change-Proposal.md) | CR-01 年度保養計畫與逾期紀錄、CR-02 保養異常追蹤 |
| 員工教育訓練紀錄系統 | 人力資源與工安 | [SAD-Training](SAD-Training/README.md) | [修改需求提案書](Change-Proposals/Training-System-Change-Proposal.md) | CR-01 應受訓與到期追蹤、CR-02 上課簽到與出席時數 |
| 工單分派管理系統 | 生產管理 | [SAD-Work-Order](SAD-Work-Order/README.md) | [修改需求提案書](Change-Proposals/Work-Order-System-Change-Proposal.md) | CR-01 停工與恢復紀錄、CR-02 分批報工與工時 |

五題的領域各不相同，修改需求也刻意錯開，因此不會有兩組交出結構相同的報告。

**五題共同的性質**：每套最多 5 張資料表、2–3 個角色；畫面用 HTML + CSS + JavaScript，一支 Node.js 小程式讀寫 SQLite 資料庫檔，在你自己的電腦上執行。每一題的修改需求都會同時動到流程、資料表與畫面，第二部分的差異分析、影響分析與畫面設計才寫得出內容。

## 四、怎麼用這些文件

| 步驟 | 做什麼 |
|:--:|---|
| 1 | 抽籤前，先讀各題提案書的〈一、系統現況〉與〈二、兩項修改需求〉，知道五題各在做什麼 |
| 2 | 抽到題目後，照該題系統的 `README.md` 安裝啟動，每一種角色都登入操作一遍 |
| 3 | 從系統整理出角色、流程、功能需求與資料，寫第一部分 |
| 4 | 讀提案書的每一項修改需求。提案書會指出在系統上怎麼看到「原有系統的缺點」，先照著操作，確認自己看到的是同一個問題 |
| 5 | 把〈請你想清楚〉逐條做出決定，再開始寫第二部分 |

第 2 步不要跳過。沒操作過系統就動筆，第一部分會寫成想像中的系統，第二部分的影響分析也會跟著對不上。系統的資料玩壞了，重新下載即可，見各系統 `README.md`〈資料玩壞了怎麼辦〉。

## 五、你可以怎麼找答案

讀提案書或操作系統時一定會遇到不懂的地方。答案多半找得到，可以從下面幾個方向找：

1. **從系統本身找。** 用每一種角色的帳號登入，把每個畫面都點過，每一種單據都從開立做到結案。邊做邊記：哪個角色能做什麼、資料在哪個畫面輸入、在哪個畫面看得到。這份筆記也是第一部分的材料。
2. **去找一張真的單子。** 五題在現場都有紙本或 Excel 的做法。用 Google 搜尋圖片或檔案，關鍵字如「異常處理單 範本」「盤點表 範本」「保養紀錄表 範本」「教育訓練簽到表 範本」「工單 範本」，可以直接看到大量實際的表單。拿來跟系統的畫面比：系統少了哪些欄位、多了哪些，每一欄是誰填、填了給誰看。答不出來的地方，就是要去問人的地方。
3. **找一位實習過的人問十分鐘。** 系上大三大四有實習過的學長姐、或修過相關課程的同學。問三個問題就夠了：這件事現在怎麼做、最常出錯的是哪一步、你覺得最麻煩的是什麼。這十分鐘的價值高過查一整天資料。
4. **把 AI 當成工業工程專家來問。** 先交代情境，再問現場的做法，例如：「你是有十年經驗的工廠品管工程師。一張品質異常單從開立到結案，現場通常會經過哪些步驟？哪一步最常卡住？」把提案書的〈請你想清楚〉丟給它，請它說明各種做法在現場的優缺點，也很好用。但 **AI 給的是一般工廠的做法，不是這一題的答案**：要拿回來跟系統與提案書對照，你自己要能說明為什麼採用。
5. **不要直接讓 AI 幫你規劃修改，自己卻說不出為什麼這樣規劃。** 就算要讓 AI 幫忙規劃，也要先自己弄懂問題：系統現在怎麼運作、這項修改要解決什麼。先懂問題，才看得懂 AI 規劃出來的東西是什麼、哪裡不適用於這一題。使用揭露義務見[SAD 課程介紹](../00-Course-Introduction/Course-Introduction.md)〈AI 工具使用揭露〉。

找到答案之後，把〈請你想清楚〉用自己的話重寫一次。寫不出來就是還沒懂。寫得出來，第二部分的〈變更申請〉就有一半的材料了。

## 六、如果讀完還是不懂

**這是正常的，不是你的問題。** 這些題目描述的是你還沒進去過的職場，看不懂的地方一定有。處理順序建議如下：

| 順序 | 做什麼 |
|:--:|---|
| 1 | 把不懂的地方寫成具體問題。「我不懂盤點」問不出東西，「盤點的時候倉庫還在出貨，那數字要怎麼算」才問得出東西 |
| 2 | 問修過相關課程的老師或實習過的同學。工管系的老師對這些現場流程都熟 |
| 3 | 上課問。這五題都是老師選出來的，可以直接問 |
| 4 | 問 AI 幫你梳理概念。但**你必須看懂它給你的東西**，採用之前要能自己說明——懂或不懂，會在口頭報告與個人訪談的問答裡直接顯現出來。使用揭露義務見[SAD 課程介紹](../00-Course-Introduction/Course-Introduction.md)〈AI 工具使用揭露〉 |

**不要用「先寫下去再說」處理看不懂的部分。** 系統現況理解錯了，後面的修改建議會一路錯到底，而且訪談時一問就出來。

## 七、有幾件事這五題都不要做

不管抽到哪一題，下面這些方向都會讓報告偏離「系統分析與修改建議」，變成重新設計、演算法或領域專業的專題：

| 不要做 | 為什麼 |
|---|---|
| 把系統整個重新設計 | 期末是依提案書修改既有系統，提案書沒有碰到的部分維持原樣 |
| 最佳化排程、需求預測、自動補貨演算法 | 演算法本身會吃掉整份報告，而課程要評的是分析與修改建議 |
| 影像辨識、AI 自動判定 | 那是另一個領域，而且你無法在報告裡說明它怎麼運作 |
| 複雜成本分析、財務模型 | 效益評估只要求列出指標、修改前的估計值與修改後的目標值 |
| 與 ERP、MES 全面整合 | 系統在本機端執行，提案書沒有要求的介接一律界外 |
| 接感測器、RFID、PLC 等硬體訊號 | 五題都假設資料由人工登記。要接硬體的一律界外 |
