# 投影片設計規範

本檔為各章節投影片版本（`0X-XXX.slides.md`）的統一設計規範。投影片以 [Marp](https://marp.app/) 撰寫，在 VS Code 中安裝 Marp for VS Code 擴充套件即可預覽與匯出 PDF。

製作新章節投影片時，複製 `reference/slides-template.slides.md` 作為起點，並依本檔調整內容。投影片是正文的濃縮版，正文的撰寫規範（用語、中英夾雜空白、粗體標記前後空白）同樣適用，見 `reference/chapter-writing-guide.md`；本檔只記錄投影片特有的規則。課程名稱、章節標題副標等隨課程而異的設定，見專案的 `CLAUDE.md`。

## 一、Frontmatter

每份投影片檔案開頭固定為下列 frontmatter，四個設定值不可更動：`marp: true` 啟用 Marp、`theme: gaia` 指定佈景主題、`paginate: true` 顯示頁碼、`class: invert` 套用深色底色。`style` 區塊讓所有圖片自動水平置中，缺少它時圖片會靠左，整份投影片的版面會不一致。

```yaml
---
marp: true
theme: gaia
paginate: true
class: invert
style: |
  section img {
    display: block;
    margin-left: auto;
    margin-right: auto;
  }
---
```

## 二、章節分隔頁

每個章節開頭需有一張分隔頁，內容只有 `# {中文數字}、章節標題` 與 **1–2 段引言散文**，說明本章要學什麼、為什麼重要。

分隔頁不加 `##` 副標，也不使用條列。引言的作用是讓聽眾在進入細節前先建立動機，條列做不到這件事——條列會被讀成待辦事項，散文才會被讀成脈絡。

```markdown
✅
# 三、{章節標題}

{一段引言散文，點出本章要回答的核心問題，以及它為什麼不像表面上那麼簡單。用具體的疑問或反直覺的事實起頭，比用定義起頭更能建立動機。}

{第二段引言，說明本章的推進路線：從哪裡出發、經過什麼、收在哪裡。}

❌
# 三、{章節標題}
## 本節大綱
- {子題一}
- {子題二}
- {子題三}
```

## 三、Blockquote

Blockquote（`>`）一律 **整句粗體**，不可只加粗其中部分詞語，也不可出現巢狀 `**`。投影片上的 blockquote 用來呈現需要被記住的一句話，整句同一種強調層級才有效；句中再挑幾個字加粗，會讓視覺焦點散掉，而且巢狀 `**` 在 Marp 的渲染結果不穩定。

```markdown
✅ > **工具會一直換，但解決問題的方法會留下來。**
❌ > 工具會一直換，但解決問題的 **方法** 會 **留下來**。
❌ > **工具會一直換，但解決問題的 **方法** 會留下來。**
```

## 四、圖片版式

投影片的圖片依用途分三種版式，不要自行混搭其他寫法：

| 版式 | 語法 | 使用時機 |
|---|---|---|
| 整頁大圖 | `![h:600](path)` | 圖本身就是這一頁的主角，例如完整的流程圖或架構圖，文字只留標題 |
| 左右背景圖＋文字 | `![bg left:45%](path)` 或 `![bg right:45%](path)` | 圖與文字份量相當，需要對照閱讀 |
| 文中右側小圖 | `![right:40%](path)` | 文字為主，圖只是輔助說明 |

整頁大圖的高度可依實際圖片比例在 `h:500` 到 `h:600` 之間微調，但同一份投影片內應維持一致。背景圖與小圖的百分比同理，不要每一頁都用不同數值。

## 五、不加圖片來源圖說

投影片版本 **不加圖片來源圖說**，這是與正文 `.md` 最大的差異。投影片的版面空間有限，一行小字的來源標註在投影時多半看不清楚，反而擠壓內容。

圖片的授權標註仍以正文為準：同一張圖只要在正文 `.md` 中依規範標註了來源、作者與授權條款，投影片即可直接引用。若某張圖只出現在投影片而未出現在正文，仍須確認其授權，並在正文或 `README.md` 的授權例外清單中補上記錄。

## 六、每頁資訊量

投影片是講述的輔助工具而非講稿。每頁以一個概念為原則，條列不超過五項、每項不超過兩行；需要長篇說明的內容留在正文 `.md`，投影片上只放能被口頭展開的關鍵詞。若一頁的內容需要縮小字級才塞得下，正確的做法是拆成兩頁，而不是調整字級。
