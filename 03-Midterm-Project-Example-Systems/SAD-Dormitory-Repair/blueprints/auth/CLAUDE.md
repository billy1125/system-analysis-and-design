# auth 子系統

登入、申請帳號、登出、圖形驗證碼。無 `url_prefix`，共 4 條路由。

本子系統的 `login_page()`、`logout()`、`captcha_image()` 三個函式與領域無關，`register()` 則多收三個住宿欄位。

---

## 路由

| 方法 | 路徑 | 說明 |
|------|------|------|
| `GET POST` | `/login` | 登入；已登入 → redirect `/` |
| `GET POST` | `/register` | 申請帳號；成功 → redirect `/login` + flash |
| `GET` | `/captcha.png` | 驗證碼圖片 |
| `GET` | `/logout` | 登出（GET 且有副作用，KI-07） |

---

## 登入的五道驗證（順序固定）

1. 驗證碼非空 → `請輸入驗證碼`
2. 驗證碼正確 → `驗證碼錯誤，請重新輸入`
3. 帳密非空 → `請輸入帳號與密碼`
4. 帳號存在、未刪除、密碼正確 → `帳號或密碼錯誤`
5. 帳號啟用中 → `帳號已停用`

**第 4 步把三種情況合併成同一則訊息**，不讓外部探測帳號是否存在。但第 5 步是不同的訊息——這是刻意的取捨：停用是管理員的行政處置，當事人有權知道自己為何登不進去。

驗證碼比對前必須 `.strip().upper()`——字元集是大寫，使用者輸入小寫時要先正規化。

> `session['captcha']` 在登入成功後**未清除**（KI-05），因此同一組答案可重放。這是本系統修補成本最低、安全效益最高的一項。

## 申請帳號的四道驗證

1. email 與密碼非空 → `請輸入電子郵件與密碼`
2. email 格式（`EMAIL_REGEX`）→ `電子郵件格式不正確`
3. 密碼長度 ≥ 8 → `密碼至少需要 8 個字元`
4. 兩次密碼一致 → `兩次密碼輸入不一致`

再加上資料層的 `sqlite3.IntegrityError` → `此電子郵件已被使用`。

驗證失敗時以 `error` 變數重新渲染表單，並用 `form_data` 回填 email、姓名與三個住宿欄位（**不用 flash + redirect**，那會沖掉使用者剛填的內容）。

新帳號一律 `role = 1`、`is_active = 1`。系統沒有「申請成為管理員」的途徑。

### 住宿欄位為什麼是選填

表單收 `dorm_building`、`room_no`、`phone` 三個欄位，**都不驗證**。

直覺上報修系統的使用者一定住宿舍，房號應該必填。但有兩個反例：新生在分配房間前就會拿到帳號；管理員與維修人員根本不住宿舍（種子帳號 2 與 4 的棟別就是 NULL）。設成必填等於要求所有管理員帳號都編一個假房號。

因此改為選填，而在真正需要的地方（報修表單）才必填。這是「**在需要的那一刻才要求**」的原則。

`display_name` 傳 `None`——註冊表單不收顯示名稱，使用者可以之後在個人資料頁補。理由是表單已經有七個欄位了。

## 驗證碼

`_gen_captcha()`（在 `utils.py`）產生 5 位字串，字元集 `ABCDEFGHJKLMNPQRSTUVWXYZ23456789` 刻意排除易混淆的 `I` `O` `0` `1`。

`GET /captcha.png` 每次都產生新的答案並覆寫 `session['captcha']`，因此頁面上的刷新按鈕只要重新請求這個 URL 即可（加 `?t=` 時間戳繞過瀏覽器快取）。

測試中不需要 OCR，直接寫入 session：

```python
with client.session_transaction() as sess:
    sess['captcha'] = 'ABCDE'
```

---

## 注意事項

**`hub` 的內嵌登入是這裡的完整複製（KI-12）。** 任何登入政策的強化都**必須兩處都改**，漏改就能從另一個入口繞過。修補 KI-05（驗證碼重放）或 KI-08（session fixation）時最容易踩到。

**登入成功時沒有先 `session.clear()`**（KI-08，無 session fixation 防護）。

## 樣板與 CSS

| 樣板 | 說明 |
|------|------|
| `auth/login.html` | 登入表單；驗證碼圖片可點擊刷新 |
| `auth/register.html` | 申請表單；七個欄位 |

兩者的 `<form>` 都必須有 `class="login-form"`，否則送出按鈕會失去樣式（`login.css` 的 `button[type="submit"]` 限定在此選擇器內）。

使用 `static/login.css`，由 `base.html` 全域載入，不需要在樣板中另外引入。
