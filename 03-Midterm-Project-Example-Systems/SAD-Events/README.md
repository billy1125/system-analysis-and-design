# 校園活動報名系統（sad-events）

以學習為目的的 Flask 教學專案：**會員登入與管理系統 + 校園活動報名子系統**。
用於系統分析與設計課程，刻意維持小規模、不做過度抽象，讓讀者能在一到兩小時內
讀完全部程式碼，並看清楚「使用者在瀏覽器上的一個動作」如何一路走到資料庫、再走回畫面。

---

## 快速開始

```bash
conda activate flask
pip install -r requirements.txt
python app.py
```

開啟 <http://localhost:4000>。首次啟動會自動建立 `database.db`，
並植入 3 個種子帳號與 5 筆種子活動。

### 種子帳號

| email | 密碼 | 身份 |
|-------|------|------|
| `user@example.com` | `password123` | 一般使用者 |
| `admin@example.com` | `admin1234` | 管理員 |
| `disabled@example.com` | `disabled123` | 停用帳號（無法登入，用於觀察停用行為） |

### Docker

```bash
docker compose up -d --build    # 建置並啟動（port 4000）
docker compose logs -f
docker compose down             # 停止
docker compose down -v          # 停止並刪除資料（重置 DB）
```

### 測試

```bash
pytest                          # 152 個案例
pytest tests/test_events.py -v
```

## 功能

### 校園活動報名（events）

- **瀏覽**：活動列表（每頁 5 筆）與活動詳情，**訪客不需登入即可查看**
- **辦活動**：任何登入會員都可以建立活動，成為該活動的「發起者」
- **管理活動**：發起者或管理員可修改與刪除自己（或任何）活動；刪除為邏輯刪除
- **報名**：填寫用餐選項與（選填的）聯絡資訊；一人一活動限一筆有效報名
- **取消與重新報名**：取消後可重新報名，系統會恢復原本那一列而非新增第二筆
- **報名名單**：公開檢視只顯示報名者與報名時間；發起者與管理員可看到完整聯絡資訊與已取消紀錄
- **我的報名**：查詢自己的全部報名紀錄，活動被撤銷後仍保留

### 會員系統

- **身分驗證**：登入、申請帳號、登出、伺服器端產生的圖形驗證碼
- **個人資料**：本人查看與編輯姓名、顯示名稱
- **會員管理**（管理員專用）：會員清單、依狀態篩選、關鍵字搜尋、分頁、啟用／停用、角色調整、軟刪除

## 活動狀態

系統依「時間」與「名額」自動計算活動狀態，五種狀態互斥，判斷順序即優先序：

| 順序 | 狀態 | 條件 | 畫面標籤 |
|:--:|------|------|---------|
| 1 | `ended` | 活動時間已過 | 活動已結束 |
| 2 | `closed` | 報名截止時間已過 | 報名已截止 |
| 3 | `not_open` | 報名開始時間未到 | 尚未開放 |
| 4 | `full` | 有效報名數 ≥ 名額 | 名額已滿 |
| 5 | `available` | 以上皆不符合 | 可報名 |

**只有「可報名」的活動接受報名。**

五筆種子活動刻意各自對應一種狀態，因此第一次開啟活動列表就能同時看到五種 badge。
時間以「相對現在的天數」植入（`datetime('now', '±N days')`），不寫死絕對日期——
否則過幾個月後五筆會全部變成「活動已結束」，狀態差異就看不出來了。

## 權限模型

本系統有兩種**身分**與一種**關係**：

| 概念 | 判定 | 取得方式 |
|------|------|---------|
| 管理員 | `role == 0` | 由既有管理員指定 |
| 一般使用者 | `role == 1` | 新申請帳號的預設值 |
| 活動發起者 | `user.id == event.user_id` | **建立一場活動就成為那場活動的發起者** |

「活動發起者」不是角色而是關係——同一個人對 A 活動是發起者，對 B 活動就不是。
這是本系統相對於單純角色制的關鍵設計：權限不只看「你是誰」，也看「這筆資料是不是你的」。

| 動作 | 訪客 | 一般使用者 | 活動發起者 | 管理員 |
|------|:--:|:--:|:--:|:--:|
| 瀏覽活動、檢視公開報名名單 | ✅ | ✅ | ✅ | ✅ |
| 新增活動 | ❌ | ✅ | ✅ | ✅ |
| 報名／取消／修改自己的報名 | ❌ | ✅ | ✅ | ✅ |
| 修改／刪除活動 | ❌ | ❌ | ✅（限自己的） | ✅（任何一場） |
| 檢視完整報名名單 | ❌ | ❌ | ✅（限自己的） | ✅（任何一場） |
| 會員管理 | ❌ | ❌ | ❌ | ✅ |

## 資料模型

四張資料表：

```
users ──┬─< events ──── event_details      （一對一，主表／副表）
        │      │
        │      └──< registrations
        └──────────────┘
```

| 表 | 用途 |
|----|------|
| `users` | 會員帳號、角色、啟用與刪除狀態 |
| `events` | 活動主表：標題、時間、地點、名額、報名期間、發起者 |
| `event_details` | 活動副表：活動內容、對象、聯絡資訊、注意事項 |
| `registrations` | 報名紀錄：報名者、狀態、用餐選項、聯絡資訊 |

**為什麼活動要拆成兩張表？** `events` 存的是列表與狀態判斷需要的欄位，
`event_details` 存的是只有進到詳情頁才需要的長文字。活動列表一次要撈 5 筆並算出報名人數，
四段長文字塞在同一張表會被一併讀出卻完全用不到。

**所有刪除都是邏輯刪除**（`is_deleted = 1`），系統不執行實體 `DELETE`。
取消報名同理，只是把 `registration_status` 改為 `cancelled` 並填入 `cancelled_at`。

**報名的唯一性由 application 層控制**，資料庫不加 UNIQUE 約束——
加了之後「取消後重新報名」只能刪掉舊列再新增，取消的歷史就不見了。

## 技術棧

| 層 | 技術 |
|----|------|
| 語言 | Python 3.11 |
| Web 框架 | Flask + Blueprint |
| 樣板 | Jinja2（伺服器端渲染） |
| 資料庫 | SQLite（`sqlite3`，WAL 模式），手寫參數化 SQL |
| 密碼 | bcrypt |
| 驗證碼 | captcha（`ImageCaptcha`） |
| 測試 | pytest + pytest-flask |
| 部署 | Docker + Docker Compose |

刻意不用 ORM、不用前端框架、不用 Flask-Login——理由見規格書 §2.2。

## 三項刻意的設計決定

以下三項在規格書 §11.5 有完整說明：

1. `events._current_user()` 加上帳號有效性檢查（少了它，停用帳號仍能報名佔位）
2. 刪除與取消的按鍵改用 `<button type="submit">`，不再用 `<a href="#" onclick>` 假裝按鍵
3. events 的訊息字串全部集中到 `tests/data/users.py` 的 `MESSAGES`
